The read-only private provenance seam reads the migration stages' source-coordinate maps; public stages still perform transformations. Missing or changed maps fail rather than silently guessing coordinates. Converter identity, source/target digest, per-source output coordinates, original information envelopes, source-owner export digests and canonical version are recorded in each projection's conversionLedger. v1 chunk rows have zero standalone output rows because their content is carried by the official stream representation.

Headers supplied by source exports retain lineage and header metadata through official migration. A canonical-only source without header evidence can only supply its existing canonical metadata; a seeded history without a provable inherited cut fails strict V3 validation. This implementation does not reconstruct discarded historical header fields from live homes. It never rewrites a canonical version.

`dsh-runtime/detail` is the only audited legacy information converter. Envelope surface operations or unconverted coordinate-bearing payloads are refused. Audited detail placement inside a collapsed stream now uses a temporary official log carrier, with exact original-to-target position verification and restoration before publication. Other ignorable native V3 events may be readable by the host but cannot be committed as fully adapted canonical records without a classified converter.

## Canonical-only V3 path (adapter 0.1.1)

Non-DSH canonical sources no longer pass through RC1's portable builder. Each original canonical event is retained in an ignorable, ordered source receipt, with its identity, sequence, content, raw payload, source and extensions intact. `restorePortableCanonical` restores this sequence verbatim and materialization checks its digest before returning. Information rows are not grouped by turn. `reasoning` and other policy-defined log-only kinds remain outside the model surface. Consecutive model-bearing fragments may form one ordered assistant message; fragments separated by a source event never coalesce across that event. Native step subdivisions keep both assistant nodes visible in RC2's one-assistant-per-step UI. Ambiguous tools, ordering or aliases fail.

Inline attachments retain their exact bytes as content-addressed objects, not text labels. The V3 content carries the actual image/file reference; the original canonical receipt retains its data URI. The optional codec `prepareResources` runs before both fresh and retained session publication. New objects are immutable, existing objects are rehashed, conflicting bytes/links fail, and no old file is replaced. RC2 attachment-local is configured by the provider to use the same Broker space as its dshHome. The independent default profile home is not treated as the attachment root. External unresolved resources and unsupported image layouts refuse conversion rather than becoming fake references.

Current actual 38-head preflight passes without writing source state. The 35 portable sessions also pass Session cold-read, exact ordered model-content comparison under canonical exposure policy, and full source restoration. All 19 inline image objects pass exact-byte checks and full in-memory raster decode. A separate synthetic official CLI profile proves actual LocalAttachmentStore class identity, configured root, exact readImage bytes and a second cold startup. These do not replace final target Launcher, Bridge/UI and crash-cycle acceptance.
