# 第四阶段：Codex 原生镜像执行计划

> 日期：2026-08-27  
> 分支：`codex/phase-4-native-mirror`  
> 前置：阶段三 continuation 能力已合入；阶段二正式部署与阶段三真实验收并行收口。

## 目标与边界

本阶段把少量用户明确选中的重要会话升级为受控的 Codex 原生双向镜像。系统只写当前明确支持的 Codex 存储契约；版本、schema、静默状态、空间、备份或恢复任一条件不满足时均零写入。

不伪造 Codex 推理或工具执行，不把普通 continuation 自动升级成镜像，不自动删除任一平台历史，也不为旧 `dsh-codex-session-sync` 保留兼容层。

## 精简验证原则

- 每个交付组只保留一个覆盖业务结果的聚焦测试，不为内部字段重复写测试。
- 故障点使用一份参数化矩阵，不为每个步骤复制测试文件。
- Codex 契约每个受支持版本只保留一套脱敏 fixture。
- 不安排独立代码审查代理、重复静态检查或逐任务全量回归。
- 全量类型检查、构建、测试、可复现打包只在 P36 运行一次。
- 真实 Codex 正在工作时不强停进程；真实环境只做只读指纹验收，写入验收在标记明确的隔离 Codex home 完成。

## 交付组 A：写入契约与预检（P29–P30）

1. 新建 `adapter-codex-native`，把 Codex 版本、关键 SQLite schema、会话索引格式和 rollout envelope 归一为可比较指纹。
2. 根据当前支持版本建立脱敏 fixture 与 allowlist；未知版本或关键 schema 漂移返回 `CODEX_VERSION_UNSUPPORTED`，并暂停相关镜像。
3. 写入前检查 Codex 是否静默、目标文件是否稳定、磁盘空间是否足够、是否存在未完成恢复。
4. 生成完整备份清单，覆盖 SQLite 主库及需要一致处理的 WAL/SHM、`session_index.jsonl`、目标 rollout 和关联路径元数据。

聚焦验证：同一测试同时证明“已知 fixture 可准备、未知版本/忙碌状态零写入、备份清单完整”。

## 交付组 B：候选存储与事务发布（P31）

1. 将平台写事务从仅 DSH 泛化为 DSH/Codex 共用的 `PlatformWriteAdapter`，平台格式知识仍只存在于各 adapter。
2. 在临时候选区完成 SQLite、索引和 rollout 的修改，发布前执行跨文件 ID、路径、计数和摘要一致性校验。
3. 按 journal 记录的顺序原子替换，失败时严格逆序恢复；启动时先恢复未完成事务，再允许新写入。
4. 数据库迁移仅增加 Codex 事务和镜像状态所需字段，不改写既有会话正文。

聚焦验证：一次“成功发布 + 中途失败恢复”事务测试，比较发布前后所有受管文件摘要。

## 交付组 C：语义映射与来源证明（P32）

1. 普通 user/assistant 文本映射为 Codex 可恢复的原生消息。
2. DSH 工具调用、工具结果、推理和无法等价转换的事件统一降格为可见的“DSH 导入记录”。
3. 每个导入记录保存源平台、源会话、源版本、事件范围和内容摘要；不得生成伪造工具调用或推理事件。

聚焦验证：一条包含普通消息、工具事件和不可映射事件的混合会话，验证正文顺序、降格结果和 provenance。

## 交付组 D：镜像状态机与元数据同步（P33）

1. 镜像必须逐会话显式启用，默认模式仍为 continuation。
2. 实现 `disabled → initializing → active → paused/busy/incompatible/conflicted → recovering` 状态机。
3. 只自动处理可证明等价的前缀快进和单边标题/归档变化；删除永远不自动传播。
4. 保存 Codex/DSH binding、共同祖先、两侧版本、最近事务和暂停原因；重复扫描和执行必须幂等。

聚焦验证：用一份表驱动状态机测试覆盖启用、安全快进、双边分叉、暂停、恢复和幂等重试。

## 交付组 E：冲突与操作界面（P34）

1. Engine API 提供启用/暂停镜像、保持双分支、选择规范主线、创建双父延续任务、显式重置、解除映射和删除确认。
2. Dashboard 沿用 Maintenance 现有风格，展示会话版本图、共同祖先、两侧分支、事务预览和恢复结果。
3. DSH 参数面板仅保留路径/策略参数和操作按钮；状态细节进入 Dashboard。
4. 高风险重置和删除必须先生成不可变预览，再使用一次性确认令牌执行。

聚焦验证：一条 API/UI 合同测试覆盖普通操作、高风险确认和过期计划拒绝。

## 交付组 F：故障矩阵与收口（P35–P36）

1. 用单一参数化测试在预检、备份、候选写入、校验、发布、索引更新和恢复步骤注入故障，统一断言零脏写或完整回退。
2. 对未知 Codex 版本、schema 漂移、Codex 忙碌和恢复未完成分别断言零写入。
3. 在隔离 Codex home 完成一次端到端镜像；对真实 Codex home 只运行只读契约探测。
4. 合并阶段二正式部署与阶段三真实验收结果，执行一次最终全量检查、构建和可复现打包。
5. 正式 DSH 只保留新的 `dsh-session-maintenance`；旧插件退出以阶段二部署记录为准。最终合并到 `main` 并推送远端。

最终命令仅运行一次：

```powershell
pnpm typecheck
pnpm build
pnpm exec vitest run --maxWorkers=1 --testTimeout=15000
pnpm assert:portable
pnpm verify:phase2-package
```

## 完成定义

- 当前受支持 Codex 版本命中 allowlist，真实环境只读探测有明确结果。
- 重要会话可显式启用镜像；普通会话仍使用 continuation。
- 安全快进、标题和归档可同步；分叉进入冲突，不静默覆盖。
- 任一失败点均可证明零写入或完整恢复。
- 阶段二、三、四的报告和源码都进入 `main`，远端与本地一致。
