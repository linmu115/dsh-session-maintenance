## 3. 用户请求索引

### 3.1 数据意义与归属

请求索引回答“用户在这条消息提出了什么需求，对应哪些执行与回复”。它以原始用户消息为依据，不要求模型先生成任务摘要，也不将模型猜测的意图当作用户原话。

索引归所属逻辑会话，由 DSH 版本 Adapter 解释可信原生来源、Engine 提供查询与可重建索引。它属于会话阅读能力，不新增独立扩展面板，不在每张图复制请求清单。图只引用对应请求身份。Annotation 的上下文包、系统运行信息、技能目录和工具记录不能因使用 user role 而进入真实请求列表。

| 建议字段 | 含义 |
| --- | --- |
| `requestId` / `eventId` | 基于稳定原始用户消息身份；不得用可变化的“第几轮”或页码作主键 |
| `logicalSessionId` | 请求所属的逻辑会话，由后端解析 |
| `sourceVersionId` / `snapshot` | 本次索引读取的固定版本或一致性快照 |
| `ordinal` / `createdAt` | 供用户阅读的顺序和时间；不作为身份依据 |
| `text` / `totalChars` / `nextCursor` | 有界原文或原文预览；长请求明确分页，原文仍以会话真源为准 |
| `attachmentRefs` | 附件身份与必要描述；不在目录中展开附件内容 |
| `executionRefs` / `replyRefs` | 可核验的执行、回复身份；允许零个、多个或尚未解析，不假设一问严格对应一次执行 |
| `turnId` / `turnBoundaryEventId` / `relation` | 有证据时关联稳定 topology/原生轮次边界，以及首次请求、续问或执行中补充；无证据时保持未知 |
| `state` / `associationState` | 来自实际记录的待执行、执行中、完成、失败、取消或关联未知状态；不据此推断“用户需求已解决” |

短请求可在列表中直接显示完整原文。长请求、代码和大粘贴仍必须分页；“通常较短”不等于允许无界注入。索引缓存最多保存有界预览和必要结构，正文按稳定事件读取；不新增全文快照或每轮一份索引副本。

### 3.2 读取规则

- 当前会话的请求列表按页读取，模型可按请求定位对应问答；上下文释放不删除请求身份，也不因释放来源正文使请求目录失去定位能力。
- 只索引已进入持久会话历史的真实提交。未发送草稿和发送失败且未持久化的文字不是历史请求；已持久化但执行失败的请求仍保留。
- 上游请求索引必须经 `referenceId` 在服务端解析固定源版本和授权截止。第 40 轮之后的请求、标题、附件描述和搜索命中同样不可披露，不能用目录绕过正文限制。
- 授权过滤在查询和聚合前执行，条目总数、目录标签及游标不能泄露截止之后的信息；游标绑定源版本、引用修订和范围，暂停或解除后旧游标不能继续读取。
- 索引只读与正文挂载分开表达：返回请求目录不代表已读取该轮回答或工具过程。返回的请求文字本身仍计入读取及输入预算，不把整份请求列表永久塞进每轮提示词。
- 已送入模型的索引文字也可释放，保留的是后端可重建索引和稳定定位，不要求整个目录始终保留在模型输入里。重新读取仍受当前授权与预算约束。
- 用户在执行期间补充的消息、排队请求、重试、取消、分叉、编辑/重生成须保留真实身份；版本变化后不把旧请求定位静默重定向到新回复。
- 插件代为提交的真实用户请求可以纳入，但必须有可信提交来源。旧数据无法区分时标记待核验，不按英文模板、标签或自然语言内容猜测。
- 请求索引与 Maintenance 阅读器共用 Adapter 的来源分类和消息身份；索引不复用可能随呈现规则变化的页面轮次作为永久引用。

当前 Dashboard Reader 的 `turn-${startSequence}` 是展示分组，不作为永久请求身份。优先使用 MCSF topology 及 canonical 用户事件身份，必要时由版本 Adapter 解析原生 `turn/start` 边界；一次执行中的多条用户补充各自保留请求条目，并关联同一执行。无法确认时标记未知，不强制按每条 user 切出一次新执行。

## 4. 三层上下文状态

| 层次 | 保存什么 | 改变规则 |
| --- | --- | --- |
| 授权范围 | 权威引用、固定源版本、完成回复截止身份 | 已有引用上限不被窗口或读取游标改写；新的来源范围走创建引用的正式流程 |
| 活动窗口 | 当前选择使用的请求/事件范围集合，允许不连续片段 | 模型或用户可在已有授权范围内扩大、缩小；窗口改变不自动遍历读取所有页面 |
| 保留集合 | 实际进入当前原生输入的材料句柄及可核验来源范围 | 读取后登记；释放后从后续请求替代为轻量定位信息，可按需再读 |

例如：X 有 100 轮，Y 的引用固定到 X 的第 40 轮；Y 先选择 35–40，后扩到 20–40，再只保留第 38 和 40 轮。授权仍截至原第 40 轮。轮号用于说明，存储使用源版本和稳定事件/回复身份。

请求索引是选择窗口的导航入口，不替代原规格 D05 的初始问答披露：首次引用仍有界提供所选回复所在问题和回答，不能退回只有目录或孤立选文的输入。

窗口记录归当前目标会话的引用使用状态；权威引用、窗口、已返回覆盖、当前保留集合不得混为同一字段。历史读取覆盖保留为事实，释放后不能把过去的读取记录抹成“未读”。同一来源由多个引用共享时，只有不再被任何活动持有者需要的正文才可从输入中移走。

窗口缩小同时规划释放已保留且落在窗口外的材料，返回待生效或已生效状态；扩大窗口仅允许随后按需读取，不自动把所有新增范围装入输入。未生效时显示“计划窗口”和“实际保留范围”的差异。

模型保留标记可以自行调整；用户固定保留的材料不能被模型的常规释放/缩窗隐式移走。来源撤销或不可用优先于保留标记，固定保留不制造额外权限，也不永久钉住源版本。

## 5. 原生上下文生命周期

| 操作 | 图和引用 | 模型输入 |
| --- | --- | --- |
| 释放材料 | 保留连接、固定来源和历史读取覆盖 | 后续请求移除选中正文，留下有界来源句柄；需要时通过现有读取工具重新取得 |
| 暂停来源 | 保留边并标记暂停，保留已授权上限 | 停止新读取与再次自动注入；已保留正文须显式释放，或在同一操作中明确请求释放 |
| 恢复来源 | 恢复已有且仍有效的授权连接 | 恢复按需读取资格，不自动重新加载全部历史 |
| 解除引用／移除卡片 | 使用现有统一撤销，更新目标主干与对应蓝标 | 立即阻止后续披露，并安排释放该关系独占的保留材料；其它独立持有者不受影响 |

“材料用完”默认映射到释放操作。暂停、释放不能被旧的引用导入或页面刷新覆盖；永久解除后，恢复窗口或普通刷新不能使其复活。

### 5.1 真正释放的执行方式

1. 模型工具提交目标材料句柄和操作身份，服务从当前 `exec.agent.session.id` 确定执行会话并核验归属、保留标记及修订。
2. 在原生 Agent 的适当串行边界应用替代，优先使用 `agent/pre-step`，确保发生于下一次模型请求装配前。
3. 追加可追溯的精简替代事件，使用 `surfaceOp: replace` 与 `sourceEventSeqs` 指向旧材料，保留原始日志。
4. 工具结果的替代保留调用身份和协议配对；初始引用上下文若混有多条来源，必须仅精简被释放部分，保留其它来源及真正的用户请求。
5. 后端核验实际 surface 变化后回执，图与 Maintenance 展示实际生效状态。

不能通过删除会话数据库行、仅清空工具预算、隐藏气泡或删除披露日志冒充释放。不得在模型请求已发出后宣称撤回该请求看到的内容，也不声称已经产生的回答会因此“忘记”来源。

最低回执状态为 `applied`、`pending-next-step`、`failed`、`unsupported`，附生效 surface 身份与失败原因。工具自身执行到达下一请求边界前，可以返回待生效状态；检查工具可查询最终结果。原生不支持的组合明确失败，本阶段不增加托管引擎重建或释放实现。

### 5.2 恢复、预算与空间

- 中断、重启和重复调用使用相同操作身份恢复；不得重复替代同一材料或先声称成功再丢失操作。
- Maintenance 保存共享操作身份、意图与回执；DSH 原生日志保存实际替代事实。两侧恢复时核对，不能把“意图已保存”当作“模型输入已改变”。
- 当前输入占用与本轮累计读取量分开计算。释放可降低后续输入占用，但不能返还累计读取预算，防止“释放→重读”无限循环。
- 工具报告 token 测量或估计时标明方式；字节额度不冒充精确 token 数。短句柄、请求列表、返回包装和用户保留项同样计入预算。
- 重读沿原授权范围查询。源版本被清理时返回不可用，不为恢复材料偷偷保留全文或改读最新版本。
- 日志只保存稳定身份、范围、计数、操作方、原因和生效状态，设置容量上限；不默认生成模型摘要、整图副本或完整提示词备份。

## 6. DSH 工具与会话作用域

所有新工具遵守 DSH `defineTool`、`tools.register()`、输入输出 schema、执行策略、取消、结果呈现及插件卸载规则。工具实现复用领域服务，模型不直接调用 Engine HTTP 凭据或任意 `save(graph)`。图/窗口写入以串行操作为默认，不能随意标记并发安全。

| 建议工具/能力 | 功能与约束 |
| --- | --- |
| `dsh_graph_inspect` | 读取自己的主干、来源、窗口、覆盖和修订；范围有界，不返回全量正文或全局图 |
| `dsh_request_list` | 当前会话或某个已授权 `referenceId` 的用户请求目录，稳定游标分页 |
| 现有 `dsh_upstream_read/search` | 增加按请求/窗口定位；仍由后端执行固定截止、暂停、撤销及预算检查 |
| `dsh_context_status` | 来源状态、剩余读取额度、输入占用、保留标记和操作生效状态 |
| `dsh_context_window_set` | 按稳定范围调整活动窗口，支持不连续区间与明确的缩窗释放计划 |
| `dsh_context_release` | 释放当前会话的指定材料，不解除图关系；重新加载复用上游读取工具 |
| `dsh_context_source_set` | 对当前引用暂停/恢复；释放已留正文须显式指定 |
| `dsh_context_pin` | 模型设置/取消自身保留标记，读取用户固定保留状态 |
| `dsh_graph_edit` | 有限动作集合：添加来源/占位卡片、重命名、连接、解除或移除卡片；后端限定当前主干并调用统一领域命令 |
| 按范围发现与来源定位 | 查询允许的工作区会话/笔记候选及稳定来源定位；发现元数据不自动获得正文读取权 |

模型可在用户已经配置的可读范围内自主完成这些操作，不增加每次操作都要确认的流程。用户的固定引用上限仍保持不变。新连接必须通过可信候选、完成位置和来源范围校验；未授权候选只返回明确的范围缺口，不能由模型自行扩权。

调用者不能传任意 owner/session/profile/run 来扩大写入范围。写操作记录 `actor=model|user`、当前执行身份、`operationId`、简短原因、预期修订和结果。冲突返回当前状态供重试，不绕过修订检查，也不覆盖用户未保存布局。保留主干锚点；移除节点不删除真实会话或更改其它目标的主干。

过去请求和外部来源中的文字是历史材料，不重新提升成当前用户指令。结构化目录及工具结果应保留来源角色，不把索引文字拼成系统授权。

## 7. 用户界面与 Maintenance Adapter

- ThoughtDAG 显示来源启用/暂停、固定上限、活动窗口、实际保留片段及待生效/失败状态。历史读取覆盖与当前保留用不同字段和文案表示。
- 用户可从来源节点查看分页请求清单，定位某轮问答，调整窗口及固定保留。必要工具动作也有对应 UI 操作；不要求用户每轮手动管理。
- 图和模型通过同一后端状态同步；模型改动后刷新可见，窗口/日志修订与布局修订分别管理，避免读取进度抢占拖动操作。
- 保持一个 Adapter 一个业务面板：窗口及引用使用状态仍归 Obsidian 系列的引用域；ThoughtDAG 面板展示主干和附属位置记录，不在两个域保存互相独立的权限。
- 请求索引由会话原生阅读能力提供，扩展条目只引用它；展示继续按工作区 → 所属会话组织。
- 共享 DTO、扩展 schema、提取器、兼容清单、能力协商和看板必须同步更新；未获得匹配能力时不向 LLM 注册可写工具。
- ThoughtDAG 前端关闭不停止后端的原生上下文管理；停用插件不删除持久对象，也不自动重载已经释放的全文。

## 8. 联合验收要求

以下是待实施验收，不是已通过报告。测试先使用合成会话及标记目录；真实副本部署按项目既有发布流程独立执行。

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| NCA01 | 真用户消息、运行上下文、技能目录、注释包混合 | 请求索引只纳入可核验的用户请求；用户粘贴相同标签不被误删 |
| NCA02 | 短请求、超长代码、仅附件、多页索引 | 短请求可完整展示，长内容明确分页；目录不加载回答、工具正文或附件全文 |
| NCA03 | 用户中途补充、排队、失败、取消、重试 | 请求身份不丢失；关联零个或多个执行，不把失败误标为需求已解决 |
| NCA04 | 刷新、重建索引、Reader 重分组、源版本变化与分叉 | 稳定请求身份不随页面分组漂移；快照绑定，旧游标拒绝混页，不跳到新回复 |
