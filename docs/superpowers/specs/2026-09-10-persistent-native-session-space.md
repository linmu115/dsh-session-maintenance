# RC1 持久原生会话空间：设计与验收规格

日期：2026-09-10。基线：Engine 0.1.28 / 插件 0.2.22 / RC1 Adapter 0.1.4，提交 `866f6b6`。

状态：用户已确认规格并授权实施。实现与自动验证记录见 [变更报告](../../changes/2026-09-10-persistent-native-session-space.md)。用户对 RC1 副本的手工验收仍待执行。

## 目标与本次范围

用户在 Launcher 启动同一实例/profile 时，DSH 直接使用已经持久化的完整本地原生会话历史。Maintenance 是会话真源，Adapter 在启动准备阶段将有变化的真源会话同步到原生目录。打开历史时不再通过 Maintenance 下载正文并生成原生文件。所有会话可发现、可打开，与 200 条预载限制无关；DSH 自身内存缓存保持按需读取。

首轮拟实现 RC1，保留其他版本既有兼容路径。ThoughtDAG 本次只 fork，不修改或安装；插件扩展数据另见同期需求文档，不在首轮实施范围。

## 现状

- `PersistentProjectionCache` 已按 Adapter 和源配置保留转换后的 JSON 会话缓存，并根据源变更日志更新。
- 每次运行建立稀疏 JSON overlay；Broker 为本次运行分配 `runtime-sessions`。
- 插件启动取得全量目录与前 200 条正文，通过官方 create/append 生成原生文件；其余会话首次打开时补齐。
- 正常退出提交事件、刷新中间缓存，然后清理本次运行目录和原生文件。

## Module 与 Interface

1. **原生会话空间 Module**：封装稳定身份、清单、启动差异同步、运行所有权、退出保留和恢复保护。Interface 输入已验证的投影目录和运行身份，输出原生持久化根目录及同步回执。Engine 调用此 Interface，不解释 RC1 JSONL。
2. **版本 Adapter**：提供原生会话编码能力，解释头部、事件序号、seed、路径编码和压缩；提供现有尾部恢复能力。RC1 的知识保留在 `adapter-dsh-rc1`。其他 Adapter 未声明该能力时走既有路径。
3. **运行插件**：取得完整目录元数据并登记事件提交的起始偏移；在持久原生模式下不 create/append 旧历史，不安装补齐会话正文的持久化包装器。项目、标题、标签等现有目录索引恢复继续执行。
4. **Launcher / Provider**：沿用 prepare / attach / drain / close / recover 生命周期，将 DSH `session-persistence-jsonl.root` 指向准备好的目录。运行控制文件仍属于本次运行。

## 目录身份和所有权

- 一个会话空间绑定稳定的 `instanceId + profileId + branchId + Adapter 格式标识`，不以 runId 为目录身份。
- 建议首版目录由 Maintenance 托管在 `projection-runtime/native-spaces/<space-key>/sessions`，通过启动配置归属对应实例/profile。这是本规格提出的物理位置，尚未创建；它与“物理放在 profile 子目录”是两种布局选择，共同要求是持久、隔离且由 DSH 原生持久化配置指向。无需把格式数据放到插件安装包内；物理路径不被第三方插件写死。
- 持久目录位于 `runs/` 之外；运行临时目录继续存清单引用、WAL、运行控制及恢复描述。
- 同一空间只允许一个运行拥有写入权，沿用现有 Engine 写入协调和运行租约；尚未完成恢复的运行阻止下一次覆盖同步。
- 格式兼容身份与 Adapter 软件修订分别记录。软件更新触发必要的重新核对；不按每次启动生成全量副本。
- 同一真源会话在该空间内只有当前原生副本。已被真源删除的会话不留在原生目录冒充可见历史；恢复后重新生成。Maintenance 自身恢复语义保留。

## 启动准备事务

1. 先完成已有未关闭运行的恢复或正常收尾；存在未解决恢复时拒绝覆盖原生目录。
2. 取得运行租约，更新现有中间缓存和本次运行映射。
3. 读取原生空间清单，校验空间身份、格式、上次运行状态和目录所有权。
4. 按稳定原生 ID 和投影版本摘要比较完整目录。未改变的会话只检查文件身份，不读取全部历史正文、不重新压缩或写回。
5. 对新增、内容变化或原生路径变化的会话调用版本 Adapter 编码；对被删除或迁移路径的旧文件制定清理项。标题等目录元数据仍由目录协议恢复，不伪造聊天事件。
6. 在受控暂存区生成变更文件，先验证编码和清单再逐项原子替换。清单最后提交。同步中断保留事务信息；下次在 DSH 启动前幂等完成，不把半份历史交给 DSH。
7. 持久记录本次运行的原生空间引用，再返回 prepare。只有整个空间准备成功才能启动 DSH。
8. 启动目录协议明确声明 `persistent-native` 模式，只发送目录元数据，不发送旧历史正文。接收方据此登记所有会话已原生就绪，并使用目录中的事件数量作为后续提交起点。

DSH 插件必须明确确认支持持久原生模式。旧插件不能将已存在的原生历史再次 create/append；版本不匹配时在运行接入阶段给出可见错误。控制补丁、运行回执和恢复描述使用独立的运行路径，不能继续假设它们是原生会话根目录的相邻文件。

原生文件头中的 cwd、目录中展示的 cwd、项目索引必须一致。不存在的项目根继续使用受控项目目录；Adapter 编码与运行插件必须采用同一规则，目录复用不能破坏已有的项目分组、空会话、seed 长度、序号和选区锚点语义。源 cwd 的可用性变化也属于启动核对范围。

完整落盘不等于全部进入内存；即使历史数超过 200/1000，也不依赖热会话正文传输。

## 运行期间与关闭

- DSH 从固定目录按原生语义读取、追加；Maintenance 插件继续监听真实事件、提交缺失后缀、执行 flush。
- 原生新会话继续通过现有逻辑身份登记进入真源；下次同步使用稳定身份，清理已被稳定副本取代的旧运行原生 ID，避免会话重复。
- 正常退出：官方 DSH flush -> Broker drain -> WAL 与真源验证 -> 更新中间缓存 -> 记录原生空间已安全关闭 -> 清理本次运行控制目录。原生目录保留。
- 不在 DSH 运行时用真源整段替换其打开的文件；其他来源的新版本在下一次启动准备时进入此空间。已有受支持的删除/隐藏控制遵守 drain 协议。
- 异常退出：恢复描述定位同一个持久原生根目录；现有 RC1 Adapter 校验已提交前缀并恢复未提交尾部，再完成真源提交与收尾。未知必要事件、序号缺口或被改写前缀继续报错并保留证据。
- 宿主明确确认进程从未启动时，prepare 失败或取消可以释放本次运行占用；已同步好的原生文件可以下次复用。仅凭“尚未收到 attach”不能认定进程未写入：进程已启动却未完成 attach 的情况需要先确认进程退出并检查可能产生的原生尾部，再收尾。不能清除仍可能存在未提交数据的活动空间。

## 一致性与空间约束

- ID 相同不足以代表内容相同，必须比较版本/投影摘要。
- 持久清单不记录正文；仅存空间身份、会话摘要、原生相对路径、运行与同步状态。
- 不为每次启动、每次打开、每一轮请求新建完整目录备份。
- 暂存文件只属于本次未完成同步，成功后可清理；不能作为常驻历史副本累积。
- 原有 JSON 投影缓存本次继续用于真源增量与崩溃恢复；本次不同时重写整个缓存体系。后续如需削减这部分容量，单独依据恢复需求设计。
- 目录文件由 Adapter 生成并受空间清单管理；不接受外部随意指定的路径、不覆盖未知用户文件。

## 验收规格

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| N01 | 首次启动，超过 200 个合成会话 | prepare 完成时原生文件齐全；用官方 RC1 list/readFrom 直接读取冷会话成功 |
| N02 | 正常退出并重启，真源不变 | 原生根目录、未变文件内容与修改时间不变；不调用旧历史 create/append，不取单会话正文流 |
| N03 | 只改一个会话 | 只更新对应会话文件；其他正文不重新编码或写回 |
| N04 | 新建、删除、恢复、cwd 迁移 | 原生目录与真源一致；没有同 ID 多路径残留和重复历史 |
| N05 | 标题、标签、项目、空会话 | 保留目前 RC1 行为，空会话拥有真正的原生文件，不伪造消息 |
| N06 | 运行追加、flush、重启 | 新增内容回写真源一次，重启后直接可读、无重复 |
| N07 | flush 前崩溃 | 从持久目录恢复未提交尾部，再允许下次同步；旧前缀不丢失 |
| N08 | 同步中断 | 可幂等继续；DSH 不启动到部分更新状态 |
| N09 | 同空间并发/未完成恢复 | 第二个写入者被拒绝，原生目录不被覆盖 |
| N10 | 不同实例/profile/格式 | 空间隔离；不兼容 Adapter 不误用目录 |
| N11 | 旧模式与回退 | Alpha2 既有行为通过回归；旧运行仍能恢复；旧构建不读取新格式控制信息 |
| N12 | 新 Engine 搭配旧插件 | 显式拒绝不支持的模式，不重复写入已经存在的历史 |
| N13 | 进程已启动但 attach 未完成时退出 | 先检查原生尾部再收尾，不能按未启动取消直接丢弃 |

测试使用标记的临时目录和合成会话。副本部署以新构建包和正式安装/生命周期 Interface 完成；交付记录版本、提交、自动验证结果、原生目录复用证据及用户验收入口。用户手工验收由用户执行，不能代称通过。
