# 会话贴纸、知识链接迁移与全局维护网络

用户于 2026-09-14 授权实施原规格 P2/P4，并确认来源更新只标记受影响会话，由用户选择后重新回答。沿用已有 P1/P3，不改变固定上游、正常 DSH Agent 运行和不复制全文的约束。

## 交付行为

- 会话贴纸为独立 `stickers` 对象，绑定稳定逻辑会话。创建独立讨论和挂接已有会话分别提供；主体打开完整会话，来源与管理动作分开。
- 普通贴纸迁入同一数据域，保持旧贴纸身份、内容及笔记中已有块和双链。原生会话、插件对象和笔记正文各自保存。
- `obsidian-links` 保存笔记身份、当前位置、块/标题、目标会话和同步状态。笔记重命名更新位置，删除/无法唯一定位显示异常；建立关系不自动注入全文。
- 全局网络在当前实例可用会话空间内聚合所有画布、会话贴纸、知识链接和已发送上游引用；跨画布搜索、来源/去向、引用状态、删除与冲突可按需查看。
- 影响分析有深度和返回数量上限，区分“来源有新内容”和“固定来源不可用”。已固定引用不会因追加消息变成非法引用，也不会自动切到最新版本。
- 用户选择受影响项后准备目标会话的重新讨论，沿正常会话提交流程执行；后台不自动启动模型，不自动递归重放。

## 迁移与写入权

逐个旧会话文档执行：核对本地与 Vault 对象 → 冻结旧写入 → 带来源摘要和稳定旧 ID 导入 → 核对回执 → 激活新写入方。失败可按原迁移 ID 重试。导入前冲突必须解决，不能以时间戳覆盖另一方编辑。已切换的对象即使扩展临时不可用也不能回退到旧写入方。

Vault 正文不搬走、不删除；保存对象映射与摘要，不创建整份笔记、历史会话或逐轮快照。旧块保留为原位置，新增或删除关联只操作所选链接。迁移冻结和回执持久保存，重启及失去响应不能造成双写。

## 验证

以合成数据验证：多位置复用真实会话；贴纸删除不删会话；引用创建失败可重试；旧对象冲突、冻结、重复导入、崩溃恢复；笔记改名与单处解除；跨画布分页、越实例拒绝；有环网络有界；来源追加与固定引用失效分别呈现；选择操作不自动发送。组合部署沿 Launcher 和现有 Maintenance 绑定流程完成，副本实际使用验收由用户进行。
