## 公开扩展注册合同草案

例：Obsidian 相关插件接入后，贡献“接入状态”“绑定仓库”“数据目录”“同步情况”栏目。用户从绑定栏目发起改绑，宿主调用 Bridge，收到确认后更新登记；未确认前显示未完成。卸载贡献方释放其栏目能力，历史数据仍可保留通用元数据。

### 注册内容

建议一次贡献注册包含稳定贡献 ID、插件身份及版本、实例／Profile 范围、所需能力、页面及栏目、数据读取和动作处理。数据 Adapter 与页面贡献可分别存在：只提供状态页不要求实现对象存储，有存储也不强制提供定制 UI。

每个插件只注册和注销自己的贡献，注册器汇总参与名单。稳定 ID 冲突不得相互覆盖；同一页面下的多个栏目有明确贡献方，释放一个插件不能清掉其他插件。卸载句柄释放代码、订阅和动作，不删除持久对象。

页面可以聚合多个 namespace；栏目数量、namespace 数量和运行插件数量不必相同。既有 Obsidian 系列分组可继续聚合相关贡献，不要求复制多个重复管理页。

标准目录、状态、表格、配置和动作栏目应可复用；定制视图由受信扩展包提供。DSH 宿主、Engine 与 Dashboard 可能在不同进程，不能将宿主函数或未安装的任意脚本直接当作浏览器组件。跨进程传递声明、数据和有名动作，定制前端资源的装载方式在实施时确定。

### Maintenance 与扩展的责任

| 负责方 | 职责 |
| --- | --- |
| Maintenance 宿主注册器 | 发现可选能力、汇总贡献、传递当前可信实例身份，处理启停、晚加载和注销。 |
| Engine 与 contracts | 唯一维护共享 DTO、受控查询与动作入口、数据归属、修订、冲突和兼容检查。 |
| Dashboard | 页面容器、栏目装载、标准目录、加载／不可用状态，以及局部失败隔离。 |
| 业务扩展 | 栏目内容、业务数据解释与动作语义；只接入其负责的 namespace 和能力。 |
| Bridge 提供方 | Vault 的有效绑定、端点和路由；维护登记不能替代它的确认。 |

插件缺席、版本不兼容、在线但暂时失败分别表示。单个栏目失败不使整个维护页失效；恢复后按稳定贡献 ID 重新挂载。已保存但缺少 Adapter 的对象保留通用元数据，正文与写入仍遵守原能力检查。

注册不扩大业务写权限。现有 annotation-records 可信镜像、managedSchema 图领域和原生上下文入口继续使用各自领域规则，不能借“自定义栏目”绕过。Engine 凭据留在受信宿主／连接层。

## 实例有效范围合同草案

Maintenance 统一回答“当前实例／Profile 能使用哪些工作区和会话”。Obsidian、Reference、Sticker 和 ThoughtDAG 等消费者复用这一结果；Bridge 的实例绑定不会再复制或编辑工作区选择策略。

建议对外提供：

- 分页读取实例的有效工作区及其会话，只读列表不激活模型，不隐式物化全部历史。
- 查询既有逻辑会话在目标实例中的当前可用性，返回原因及必要的原生映射。
- 提供范围修订或变化通知，使设置页、会话选择器和扩展栏目及时失效缓存。
- 在实际关联、引用投递及需要访问会话的操作提交时重新核验身份和范围；不能仅依靠前端先前的筛选结果。

状态至少能表达可用、当前实例未同步、暂时离线、原生映射未就绪和会话已删除。能力缺席与空范围不同；一次查询失败或目录中没有出现会话，不能被解释为删除。

“当前实例未同步”意味着旧链接和已保存引用继续保留，原实例／工作区／逻辑会话身份不变；用户点击时显示原因，不自动转到另一个实例。重新勾选后使用原身份核验，映射就绪才恢复。范围撤销不会隐式清除会话历史、引用正文、图对象或 Vault 标记。

各 Vault 不可缩小或扩大实例同步名单；可保存带修订的显示缓存。没有 Maintenance 的独立 Bridge 使用原生实例目录，其独立模式不伪造维护范围或维护身份。

施工核查确认当前 RuntimeBroker 只支持 projectSelection.kind=all；历史 workspace-sync-policy.json 和 Codex 来源导入选择都不是 DSH 目标范围。2026-09-18 用户明确授权在 Maintenance 新增“给实例分配工作区会话同步”功能，只有选中的工作区内容才在 DSH 与真源之间同步。因此本项目新增自己的 DSH 目标实例策略作为权威来源，Bridge／Vault 只消费其有效结果；这项授权替代此前“查找已有 DSH 策略入口”的实施假设，不替代现有 Codex 来源策略。

新增策略须按稳定 DSH 实例身份保存，运行 Profile 使用该实例范围，区分全部工作区、显式选择和空选择。为现有未配置实例保留原来的全部同步行为。用户明确选择 Maintenance 自己的会话分类工作区，不使用 DSH 文件夹路径项目作为分类权威。未分类会话单独可选。保存后的策略在实例下次启动时生效，页面同时显示当前运行范围与已保存范围。每个运行在投影前冻结策略快照，关闭和恢复仍使用该快照；双向过滤作用于投影与回收，实际回写事务内核验该运行有效范围及当前会话归属。新保存范围不能截断当前运行的未完成写入。取消工作区后不得把未投影或未回收的数据视为已删除，不清理真源历史；恢复后核验原逻辑映射。实例自身没有 Maintenance 时仍按其独立原生能力运行。

## Obsidian 接入与数据责任

Obsidian 系列可以通过公开接口组合绑定信息、在线连接、目录和同步栏目。绑定动作按 Bridge 的预期修订执行并保存确认回执；离线的改绑请求只能显示等待完成，不能提前更改生效目标。

维护对象继续按当前实例／Profile／namespace 归属和 writer 保存，绑定登记位于实例级管理栏目，不伪装成某会话拥有的业务条目。Bridge 全局按 Vault 校验独占绑定，不能仅通过在每个实例分区各写一个对象来保证唯一性。

已托管对象在 Maintenance 离线或移除后不可自动恢复旧本地写入；基础插件可以正常启动与运行独立能力，受托管的操作明确呈现暂不可用。未来若需要退出托管，应另行提供可验证交还过程，本次不实现。

## 实施结果与非目标

当前没有需要用户再次确认的产品选择。实现采用结构化栏目 DTO，通过受信宿主注册，不跨进程传页面函数；公开类型出口为 dsh-session-maintenance/business-pages。实例策略采用持久运行快照，投影、缓存与回写使用同一运行范围。旧未配置实例保持全部同步，当前运行完整回写与新运行范围隔离已有合成验证。当前提供方源码合同与测试边界见 [实施记录](../../project/records/implementation/scope-business-pages.md) 和 [验证记录](../../project/records/verification/scope-business-pages.md)。

不新增 Harness Adapter 来承担业务注册，不实现跨实例自动打开、每 Vault 工作区筛选或未来 Obsidian 操作插件具体功能。此次新增 DSH 实例同步范围，不扩大 Codex 原生回写权限。
