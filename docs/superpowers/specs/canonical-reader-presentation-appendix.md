# 会话阅读展示需求附录

本附录只约束 Maintenance 会话阅读，不修改现有会话真源、模型上下文或扩展数据归属设计。

## 功能要求

1. 用户自己发送的正文与助手最终可读回复留在每轮主视图。过程中产生的运行快照、技能目录、插件材料、工具过程、推理和较早助手回复集中到一个默认折叠的“本轮过程”入口；工具摘要按调用次数计数，配对结果不重复计次。
2. 一轮以可确认的用户消息界定；首次用户消息之前的准备记录附在首轮。上一轮回答后的连续非执行准备材料跟随下一次用户输入；已有工具调用及结果留在原轮。没有用户消息的历史片段仍有可查看的记录入口。连续用户输入不合并删除，工具消息不能冒充新用户输入。
3. 分类依据来自 Adapter 解释的原生来源元数据；`role=user` 不是“人类亲自输入”的充分条件。正文中的模板、英文、XML、JSON 或伪造来源示例不参与自动分类。缺少可信来源时采用保守展示。
4. 运行上下文清空、技能目录更新及孤立工具结果保留可查看记录，不为清理 UI 删除历史。
5. 真实工具 callId 用于配对；不能按相邻位置、相似名称或结果正文猜配对。

## 性能与读取要求

1. 首屏不下载整套过程正文。目录仅返回来源标签、计数、固定事件标识和受限的问答文本页。
2. 过程未展开时不挂载其 Markdown/JSON。展开过程目录仍不自动下载每一条正文；单条展开后才读取。
3. 长正文、工具结果和原始记录都提供有界页、总长、下一页位置；通过翻页可以读取完整内容。不得仅截断尾部而没有继续入口。
4. 翻页固定同一会话快照；发生更新时提供“重新加载会话”，取当前快照重置阅读位置，不能只重试过期快照。请求会话与事件归属必须一致，所有接口沿用本地 Engine 权限。
5. 会话切换、折叠和卸载取消读取；旧响应即使延迟完成也不能影响当前页面。页面替换读取，不无限叠加大 DOM。

## 数据与兼容要求

1. 展示语义只属于查询 DTO，不重写 Canonical role/kind/content/digest/rawPayload，也不改变模型投影的 `model-visible/log-only` 策略。
2. 当前阅读最新 Head；旧版本阅读/比较功能继续使用原有接口，不能把当前目录接口宣称为任意历史版本阅读。
3. 保留旧 `getCanonicalSession` 契约。新版实际看板使用分页 API，不因新接口出错静默退回全量下载。
4. 不新增每轮上下文全文备份，不复制完整会话库来实现阅读缓存。

## 验收

- 同一句 `Current runtime context` 作为真人正文正常显示，带可靠宿主来源的快照在过程入口显示。
- `<available_skills>` 真人示例不被误折叠；真实技能目录被识别。
- 每轮问题、最终回答均可完整读完；中间回复、调用及结果不丢失。
- 上一轮回答之后、下一问题之前的运行上下文与技能目录归入新轮；上一轮工具调用和结果不被移走。
- 大输出没有进入初始网络响应或未展开的 DOM；分页内容连接后等于原文，包括 emoji 等非 BMP 字符。
- 改换会话或关闭过程时取消在途请求；迟到响应不串页。
- 快照失效后可重新加载当前会话并恢复阅读，不会反复提交旧快照。
- 前后数据库事件逐字一致，原投影策略及旧 API 回归通过。

实现和当前验证记录见[变更报告](../../changes/canonical-reader-process.md)。
