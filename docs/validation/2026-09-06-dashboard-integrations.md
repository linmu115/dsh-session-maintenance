# Maintenance 看板与接入管理候选验收

日期：2026-09-06。候选版本为 Engine 0.1.17、DSH 插件 0.2.20、Launcher 0.2.3。

## 交付范围

本批按已批准的两项调整实施：首先支持 Launcher 管理的 DSH 与本机 Codex，以实际组件和配置检查决定能力；将实例接入、工作区同步范围和 Codex 原生同步可行性分别处理。所有施工位于隔离候选分支，未替换生产安装。

| 页面或组件 | 本批行为 |
| --- | --- |
| 会话 | 默认入口。左侧工作区与会话目录持续保留，右侧静态 Markdown 阅读；无模型输入、发送或正文改写。工具及原始记录默认折叠。 |
| 同步 | 独立保存工作区名单，自动包含未来新会话。显示保存状态和原生能力状态；范围配置尚未启用原生回写。 |
| 恢复点 | 最近删除及撤销删除直接可见。旧保护记录先查询来源兼容性，支持时再选择目标生成预览；事务恢复保留在高级区域。 |
| 存储空间 | 解释已登记、受保护和候选回收占用；保留预览、隔离、宽限期恢复和最终释放核对。 |
| 设置 | 自动发现接入对象，提供接入、检查、修复、断开；Adapter、运行诊断与技术细节收在高级区域。 |
| Launcher | 发布当前进程、程序摘要及四阶段生命周期能力；Engine 独立验证，按选定实例和 profile 消费绑定。 |

DSH 首次接入使用实际官方 CLI、选中 Home/profile 和 Engine 内嵌同版插件包，不要求使用者编写 Adapter 或 Hook。包、补丁、入口和 Launcher 能力不满足已验证条件时明确说明原因。未知的已有 Hook 提供者不会被覆盖。

Codex 默认来源来自 Engine 可信启动环境，按真实路径去重并通过实际读取适配器检查。接入仅登记 Maintenance 来源；当前进程即可列出、导入和扫描，重启后保持绑定。已存在的多 ID 同目录来源仍能单独接入。扫描以每批开始时的来源集合为准，运行中新增来源进入下一批。

浏览器核对包括：Markdown 标题、列表、表格、引用及代码显示；切到设置/恢复/存储后返回仍保留所选会话与左侧目录；默认 Codex 首次点击后由“可接入”变为“已接入”，原生能力继续显示不可用；最近删除无需展开高级区域；存储统计正常加载，五项统计和内容间距完成视觉修整。本次没有做真实 RC1 安装后的浏览器验收，也没有把协议探针等同桌面回答引用验收。

主控与独立审查发现并修复的问题包括：平台原生消息包装不应由 Dashboard 解析；祖先开发包不能被误认为选中实例已安装组件；断开后的早期接入操作不能重新发布绑定；多 ID 同目录接入应优先匹配精确 ID；新增来源不能被扫描服务的启动快照遗漏；恢复预览必须核对所选版本和正文对象；看板凭据过期需要可理解的重开提示。

测试使用标记合成目录。协议可行性探针使用临时 Codex Home 与本机假模型，没有向真实会话写入，也没有调用外部模型服务。原 Maintenance 与 Launcher 基线工作树均经核查保持干净。

## 明确的能力边界

1. **完整 Codex 原生双向续聊尚未实现。** 0.153.4 的公开接口探针未找到将 DSH 已完成回答追加为指定原 ID 的完整原生轮次的入口。`inject_items` 只进入模型上下文；`resume.history` 不能同时保留原 ID 和原生历史。原 ID 的普通 `resume + turn/start` 能生成并持久化 Codex 执行的新轮次，属于另一种执行方式，不能代替既有答案导入。
2. 名单包含未来会话，但目前只是保存的用户范围配置。原生 writer 为关闭状态；未来仍须在入队和提交时按可信原生归属核对，不能用可变的界面工作区分组充当写入授权。
3. 撤销删除恢复的是会话可见性，**不将正文回退到任意历史版本**。当前 Canonical 自动保护点不冒充可用的旧版恢复点；本批未新增无完整恢复路径的手动创建入口。
4. 本批没有开启五天正文版本自动删除。现有会话版本继续保留，副本治理沿用已经实现的引用保护和隔离流程。
5. 接入状态说明已验证组件与绑定，不代表 DSH 此刻已经运行。实际 RC1 安装、启动关闭及用户操作验收属于下一次部署步骤。当前生产安装保持原版本。
