# DSH instance workspace settings and read APIs

The Dashboard synchronization page now contains a separate DSH instance workspace panel. It reads a trusted DSH instance directory rather than treating an integration target hash or a Codex source as an instance identity. The form supports all workspaces, selected canonical workspaces, explicit empty selection, and an independent unassigned-session checkbox. Profiles and Vaults share the instance policy.

Saved configuration and currently active run snapshots are displayed separately. Saving does not activate a scope; the UI explicitly states that the next instance startup uses the saved policy. Revision conflicts reload the latest configuration for a fresh decision. Switching instances, refreshing the directory, and unmounting abort outstanding work and ignore late read/save responses. Deleted or unavailable selected workspaces remain visible so the user can deselect them rather than silently losing historical IDs.

The shared configuration DTO contains policy, active scopes, workspace directory and pending activation. `InstanceWorkspaceService` depends only on injected configuration/write/effective-scope/availability/instance-directory ports. It validates provider identity boundaries, refuses unregistered instances, and translates policy conflicts to HTTP 409. Its routes must be invoked after the existing Engine authentication, origin and CSRF guards. Routes provide the trusted instance directory, GET/PATCH policy configuration, effective profile scope, and logical-session availability. The authenticated local API client validates responses and preserves structured error status/code without exposing its secret.

Focused tests cover saved-vs-active separation, scope identity mismatch, unknown instances, bounded routing, explicit empty/unassigned selection, 409 reload, cancellation and late results across instance navigation. Existing Dashboard reading and local API client regressions are also run. UI controls reuse existing Dashboard components and theme classes, native labeled controls, form submit behavior and visible status/error feedback; no new motion or color palette is introduced. Real-browser viewport/theme inspection is not part of this isolated component test run.

Engine/composition/server wiring, immutable run snapshots and commit enforcement are implemented separately. This change never edits Codex mapping semantics or activates a saved scope from a settings save.
