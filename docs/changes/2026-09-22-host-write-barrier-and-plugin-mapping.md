# 宿主写入屏障与插件数据映射

## 用户修正与实施范围

来源：当前任务用户批注。Maintenance 不拥有通用图模型；只保留插件数据的来源和类型标记及原数据，需要还原时交给对应插件 adapter。目标没有对应插件则不映射，插件握手由插件 adapter 负责。此要求替代上一条答复中“核心拥有通用图模型”的表述。

用户要求补齐宿主独占写入：阻止目标的新写入、等待已有操作正常落盘/关闭、执行同步与状态刷新、释放屏障，失败可恢复。实现不依赖 Launcher 停止，不修改真实实例作为测试。

后续用户进一步明确：插件 adapter 必须把数据还原到插件正常读取使用的位置，验收是从抽象数据还原后功能保持，不能只凭数据存在或格式通过。插件 adapter 因此负责还原位置、幂等写入及通过插件正常读取接口回读验证；Maintenance 只记录来源与不透明内容。

方案：把写回作为宿主内的一次完整操作执行，避免 Engine 在跨进程租约过期后继续直接写文件。宿主 adapter 负责身份、访问屏障和归档接口；核心只发送规范会话及范围。测试覆盖并发、超时、失败释放、归档回读、缺插件跳过与源数据保留。

## 结果

源码已接通宿主写回提供者和插件映射接口，未部署到真实实例。实现与合成验收范围如下。

### 宿主写入与回执

- Engine 经核验的本地宿主端点提交整次操作，不再由调用方持有跨进程租约后直接写实例文件。请求绑定实例、Profile、Home、PID、进程开始时间和本次操作 ID；凭据只在本地内存传递。
- 宿主屏障封住目标会话的新 prepare/enter、写句柄 open/create；已有会话走正式 flush，等待自然结束及写句柄成功 close。其他会话不在屏障内。未正常收尾则返回 busy，不强停 Agent、不调用 Launcher。
- 取得官方 JSONL persistence 的内核写锁，覆盖迁移前后目录；锁内再次比对 drain 前的持久化修订。已有对话在 drain 期间新增内容则拒绝旧快照覆盖。
- 临时原生日志完成 fsync 后替换；随后通过宿主工作区队列恢复归档/取消归档、使投影缓存失效、通过宿主读取路径重载会话，并调用插件 adapter 回读验证，最后释放锁和屏障。
- 刷新或锁释放失败会保留目标隔离及原恢复回调；后续操作必须包含原完整范围，并先完成旧恢复。释放成功的锁不重复释放。Engine 校验完整回执及全部会话绑定后才确认身份，错实例、旧进程、重复/遗漏绑定或失败列表均不记成功。

入口：[宿主处理器](../../plugins/dsh-session-maintenance/src/host-workspace-sync.ts)、[宿主写入屏障](../../packages/instance-integration-dsh/src/host-write-barrier.ts)、[调用适配器](../../packages/instance-integration-dsh/src/host-workspace-sync.ts)、[共享协议](../../packages/contracts/src/host-workspace-sync.ts)。这些宿主机制没有进入规范会话存储或同步协调核心。

### 插件数据的保留、恢复与续写

Maintenance 保留来源 namespace、数据类型、记录身份及不透明原数据，不把插件图或插件引用变成核心业务模型。恢复协议是 [PluginDataMappingAdapter](../../packages/contracts/src/plugin-data-mapping.ts)：对应插件 adapter 完成握手、按目标和记录身份幂等恢复、通过插件自己的正常读取路径验证。宿主 adapter 提供目标会话与不透明宿主上下文（DSH 的 cwd 等）；Maintenance 不解释这些字段。

宿主公开 `maintenancePluginDataMapping` 注册服务。插件 adapter 注册自己的 namespace；只有它与对应运行插件握手成功，才执行 restore。restore 可返回宿主事件，或将数据放入插件自己的存储并返回回执；verify 在宿主刷新后执行。配置里出现插件名称不算握手，restore 成功本身也不算功能恢复。

目标缺插件或握手不通过时不恢复该插件记录，源数据继续保留。宿主格式 adapter 负责连续序号与其已知引用的重映射；适配器保存源前缀指纹、实际输出前缀和序号映射回执。缺插件的目标继续追加普通对话后，反向读取保留原插件记录和新增事件原载荷，再次映射仍生成连续序号。引用指向被省略的事件、且没有可证明映射时拒绝恢复，避免伪造引用。

### 尚未完成与适用边界

- 这是当前 RC2 JSONL 宿主的源码提供者；真实实例尚未安装此修改。需要完整宿主服务，managed Broker 或其他持久化实现不会被当作可用目标。
- ThoughtDAG、Obsidian、GPT 等真实插件还需各自注册和验收握手/恢复/回读实现。当前证明的是接入机制与合成插件的功能往返，没有证明这些真实插件已恢复全部功能。任意未来数据类型、跨格式迁移、派生分支及复杂插件引用也未全部验收。
- 活跃 Agent 仍按正常生命周期完成，超时拒绝同步；不把 flush 当成已取得写入权。正在执行且尚未返回的 flush 不会因调用方超时而被放行。
- 隔离恢复状态属于宿主进程，未实现跨进程崩溃的持久隔离事务，也未实现整个工作区和外部插件存储的原子回滚。工作区元数据使用宿主队列，但没有证明全部 UI/插件元数据操作都处于同一同步事务。
- Engine 中旧图/引用业务 API 及其他遗留具体宿主入口仍需迁出；全局架构解耦不标完成。旧文档关于“核心图领域”的描述只保留为遗留实现说明，不再作为当前需求。
