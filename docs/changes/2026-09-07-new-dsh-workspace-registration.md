# DSH 新工作区会话登记修复

Engine 0.1.21，Maintenance 插件保持 0.2.21；无数据库结构和外部协议变更。

## 根因与影响

Launcher 成功创建运行后，Runtime Broker 的 registerSession 只接受已有 canonical project root 或当前投影目录。普通新工作区不在这些记录中，首次发送在真源登记步骤抛出 `Live-created DSH session cwd has no canonical project root`。该检查将项目归属查询错误地当成创建新 DSH 会话的必要条件。项目映射清理后可用根记录仅剩选中项目，使问题暴露得更明显。

真实只读核验确认：报错路径没有对应项目根；rc1 运行与 Engine 健康状态正常。首次诊断用单次 Zstandard 解压只读到会话头，这一判断不完整；使用 Adapter 的逐帧解析后确认另有 7 条持久化记录，包括权限准备、包含原始输入的 inbox 记录以及失败轮次的开始/结束，没有完成的助手回答。该问题由 Engine 的登记限制触发。

## 修复边界

- 已有项目和运行生成的已知目录沿用原有映射。未知普通绝对路径自动登记为 Maintenance 本地项目，项目 ID 根据规范化完整路径稳定生成，重复请求和路径大小写/分隔符变体不会生成重复项目。
- 本地项目的来源为 maintenance，Codex source ID 为空；不会写入或扩展 Codex 项目名单，也不按 cwd 增加 Codex 来源会话。
- 运行身份验证仍先于项目登记；未知运行临时目录、相对路径及歧义的已有项目根仍拒绝。项目记录和根记录共同提交或回滚。
- 下次名单激活保留活动的 Maintenance 本地会话及合法活动 DSH 后继。保护集合和恢复集合分开，旧的已删除本地会话不会被恢复；原 Codex 名单切换的恢复语义保留。详见 `2026-09-07-local-dsh-project-retention.md`。

## 验证

- 先使用真实 Engine、RC1 Adapter、SQLite 与合成 Codex 目录复现相同错误，再实现修复。
- 集成回归覆盖新工作区登记、首条消息保存、重复登记、正常关闭、重新应用 Codex 名单以及从真源重投影后的内容和路径。Codex 原始文件树校验值和名单保持不变。
- 边界回归覆盖运行权限、临时目录、规范化路径并发登记、根记录写入失败的回滚及非完整绝对路径拒绝。根相对 Windows 路径先观察失败后修复。
- 本地会话保留回归覆盖多次空名单启动、合法派生链、已删除父子、错误 authority/origin、误挂在本地项目的 Codex 镜像以及原选中 Codex 派生恢复。
- 聚焦回归 4 个文件、27 项通过；全量回归 195 个文件、770 项通过（177.12 秒）；完整构建通过。实际部署回执保存在本次独立发布目录，包含源码提交、包校验值、运行收尾、安装文件验证和真实数据核验。

## 运行更新

更新前保留活跃数据库一致快照与当前运行副本；通过正式生命周期关闭 rc1 后切换 Engine。旧运行因该新会话缺少登记而进入 recovery-required，需补齐这一条会话的登记意图，再用现有未完成登记恢复流程回放。全部原始 inbox 记录须保存在 Adapter evidence 中；不将 inbox 操作伪造为已完成对话消息，也不删除原始压缩文件来绕过回收。插件包内容保持一致，无需改动其他插件或五项 Codex 名单。保留原始输入后，用户可继续发送。
