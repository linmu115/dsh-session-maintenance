# 会话阅读器：按轮阅读与按需过程

## 问题与结果

DSH 将运行上下文、技能目录等材料作为有来源标记的 user-role 消息持久化。旧看板只按 Canonical kind/role 渲染，因此这些自动生成材料也显示为“你”；同时所有事件正文和原始 JSON 随完整会话一起返回，折叠的 `<details>` 仍提前挂载内容。

新阅读器保留每轮用户正文与最后一条含可读文字的助手回复。运行上下文、技能目录、工具调用及结果、推理和其它过程记录放在同一默认折叠的“本轮过程”入口。较早的助手回复也可在过程入口查看，不删除内容。调用与结果按明确的 callId 配对，孤立结果仍独立显示。摘要按工具调用次数计数，调用与结果不重复算作两次调用。

上一轮回答之后、下一次用户输入之前连续出现的运行上下文、技能目录及插件准备材料归入新问题这一轮。如果中间再次出现工具执行等过程，则保留在此前一轮；已发生的工具调用和结果不会随准备材料转移。

## 实现边界

- Adapter 只读解释原生来源头。真实 runtime snapshot、skill catalog、明确的插件上下文与普通用户消息分别展示；不按英文模板、XML 标签或正文中的 JSON 猜来源。用户粘贴相同文字仍保留在主视图。
- 不改 Canonical kind、role、content、digest、rawPayload、投影策略或版本。API DTO 仅服务于阅读，不改变后续模型可见性。
- SQLite 向应用返回标量来源目录；过程列表没有工具参数、结果正文、sections/entries 全文或原始事件。大正文在数据库查询中按 Unicode 码点截取后才跨入应用。
- 当前查询遍历标量事件目录来确定轮界及最后回复，过程列表也会核对该轮的标量目录；超多事件仍有查询成本。没有增加全文备份、持久阅读缓存或另一套会话库。
- 当前主阅读接口使用当前 Head，与原静态会话阅读入口一致；不提供历史 `versionId` 选择。历史版本/比较接口和旧 `getCanonicalSession` 契约均保留。

## 新接口

接口沿用 Engine 现有 bearer 或 Dashboard cookie、Origin 与 CSRF 检查。

| GET 路径 | 参数 | 返回 |
| --- | --- | --- |
| `/v1/canonical/sessions/:id/reader` | 首次可空；之后 `snapshot`、`cursor`；`limit` 默认 6、最多 10 | 轻量会话信息、一页轮次、用户/最终回复各前 4096 码点、过程计数和下一页位置 |
| `…/reader/process` | `snapshot`、`turnId`、可选 `cursor/limit`；默认 25、最多 50 | 过程摘要与事件 ID；配对的调用和结果共享目录条目；没有正文 |
| `…/reader/events/:eventId` | `snapshot`、`format=text/raw`、`offset`、`limit` | 默认 8192、最多 16384 码点，实际总长与下一段偏移；事件必须属于该会话 |

snapshot 绑定逻辑会话、Head、内容变更修订及事件目录末尾。继续读取时发现变化返回 409，不混用新旧页面。界面提供“重新加载会话”，重新读取当前快照并重置阅读位置，避免一直重试过期快照。首屏中的长用户/助手正文也显示明确的“继续读取”，没有静默截断。偏移为 Unicode 码点，不能当作 JavaScript UTF-16 下标。

新客户端提供三项 reader 方法。实际部署的新看板会使用这些方法，不再为了首屏调用全量 `getCanonicalSession`；接口失败不会自动退回全量读取。仅不具备新方法的旧嵌入客户端/测试 API 保留旧读取兼容路径。

## 展示与取消

- 未展开过程时，不请求过程目录，也不挂载其 Markdown 或 JSON。
- 展开过程后仅请求摘要；继续展开单条才读取正文，工具调用/结果分别选择。
- 过程页、正文页使用替换翻页，避免无限累积 DOM；用户和最终回答可通过上一段/继续读取逐段读完整。
- 折叠、切换事件、切换会话和卸载组件都会中止相应请求；即使传输稍后仍返回，旧响应也不能进入新页面。
- 旧事件组件的原始记录与补充记录也改为展开后才挂载，但旧 API 本身的完整返回契约不变。
