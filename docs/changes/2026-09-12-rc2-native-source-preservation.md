# RC2 native source and runtime detail preservation

The first read-only preflight rejected all three live native DSH histories: exporter and consumer sorted object keys differently, and the official historical source whitelist did not include Annotation Core. A subsequent probe exposed detail cards interleaved with assistant chunks.

- Native source exports declare `sha256-json-utf16-v1` and share a locale-independent serializer. Array order remains significant. Canonical object digests are unchanged. Unknown transport digest algorithms and content mismatches are rejected.
- Only the exact Annotation Core schema-v1 user-context source is admitted through a temporary, uniquely identified plugin attribution while the official structural migration runs. Its original source is restored before V3 validation and publication. All message copies must survive. No arbitrary source kinds or arbitrary JSON payloads are rewritten. The original set ID, user message ID, digest and source kind remain available to Core rendering and reference tools.
- Only audited `dsh-runtime/detail` log events use an ephemeral `feedback/record` carrier. The official converter places this log row while coalescing streams, preserving its provenance through actual migration maps. The original type/data is restored with `ignorable:true` before validation. No carrier reaches the native output. The ledger records original and target coordinates; missing/duplicate carriers or changed coordinate mappings fail closed. Unknown events and detail payloads with unclassified coordinates still reject.
- Migration converter identity is now `migration-2`. Source digests identify the original artifact, including original sources and detail payloads. Persisted canonical history is not rewritten.

Evidence: 19 focused tests in four files passed; the added flat-V0 assistant/tool differential regression also passed with the eight-test source subset (official migration equality, streams, fork cut, cold V3 context, source contract and Annotation Core preservation). Contracts/adapter SDK build and V3 typecheck passed after the concurrent resource contract was built. The read-only native-history probe then accepted all three actual native histories; database, WAL and config SHA-256 values were unchanged. Probe/report are in the workspace diagnostics `canonical-rc2-native-source-preflight.*`. This does not claim that portable Codex histories, attachment publication or Launcher activation have passed; those are separate work packages.

Independent review found an early traversal regression for legacy flat V0 assistant/tool envelopes. Message-slot traversal now leaves absent nested message fields to the official normalizer; explicitly malformed nested values still reject. The regression test compares the complete output against the official strict/current restore.
