# SM-02：历史元数据快照与兼容迁移

日期：2026-09-05。基线：`0333e18`，包含 `a6b4053` 看板入口与 `4b49927` 身份、删除、RC1 空会话修复。施工分支：`codex/maintenance-sm02-metadata-20260905`。本项对应审查 E01。

旧实现读取历史正文时使用当前标题、标签与归档状态，并把版本 ID 返回为内容摘要。现在每个版本独立保存元数据；改名、标签与归档产生复用原正文对象的新版本，历史派生读取所选基线的已验证快照。

## 存储与共享契约

- 迁移 **017** 新增 `version_metadata_snapshots`，以既有版本 ID 为主键，保存完整 JSON、可用状态、恢复来源及本地首次持久化时间。版本、快照、父边、当前 head、必要目录变更和回执仍处于原有事务边界。
- 新版本由 SQLite 插入触发器先登记 `unknown` 与当前本地 UTC 时间，再由写入操作保存经摘要验证的快照。覆盖所有版本 SQL 写入口，即使旧调用者只提供摘要而没有可证明的元数据，也会有明确的未知记录及本地时间。
- 已验证的快照及其首次保存时间不可修改；未知记录只能升级为摘要匹配的快照。重复版本写入不改变快照、恢复来源或首次保存时间。
- `CanonicalVersionRecord` 移入 `packages/contracts`，Engine 保留原导出位置的类型再导出。共享 `VersionMetadataSnapshot` 提供 `metadataAvailability`（`available` / `unknown` / `corrupt`）、`metadataProvenance` 和 `firstPersistedAt`。看板详情的 `headMetadata` 与客户端严格 schema 同步，后续 SM-07 可直接消费。
- `bodyDigest` 是正文摘要，`metadataDigest` 是元数据摘要，`contentDigest` 是 `hash({ body, metadata })`；版本 ID 继续由逻辑会话、父版本、正文摘要和元数据摘要计算。未知或损坏元数据返回 `metadata: null`、`contentDigest: null`，正文仍可读取。

## 写入口覆盖

| 入口 | 处理 |
| --- | --- |
| `SqliteCanonicalSessionEngineStore.commit` | 普通 Codex 观察、DSH 原生导入、追加与派生均在事务内保存快照；校验版本身份、三类摘要及当前会话元数据一致性；拒绝带历史 head 的无版本元数据变更 |
| Codex 快速改名 | 复用 `advanceCanonicalSessionMetadata`，保存独立快照，复用正文对象，保持活动时间与来源权限检查 |
| 普通 Engine 改名 | 使用版本本身的 workspace 构造相同正文，修复当前目录变动时与快速路径生成不同版本的问题 |
| Dashboard 标题、标签、归档修改 | 在既有事务中同步调用同一元数据版本操作；目录写入失败会回滚版本、快照、head 和变更日志；归档重复请求不另造归档时间 |
| 旧 `putVersion`、`recordObservedVersion` | 从不可变 normalized 正文提取 `{title, archived}`，只在匹配存储摘要时保存；缺少可证明元数据保留未知。旧观察器遇到已激活 Canonical 会话时，元数据修改也经统一版本操作 |
| Canonical 激活迁移 | 在候选库事务中从所选旧 normalized 正文恢复匹配快照，保持旧版本 ID、正文对象、摘要与父边 |
| 删除、恢复 | 不改写快照；原墓碑、目录、精确身份、回执顺序保持。尚无版本的空会话元数据在首次保存正文时进入首个版本 |

元数据修改同时更新 Canonical/head ID，原有轻量变更日志触发器继续产生投影失效信号；没有新增另一套投影更新机制。

## 旧数据、错误与保留时间

迁移 017 先为旧版本登记 `unknown` 和 `firstPersistedAt: null`，再尝试当前行的 Canonical/legacy 候选元数据；只有候选的 canonical hash 与该版本 `metadata_hash` 一致才恢复。迁移不会用源观察日期、旧 `created_at`、文件修改时间或升级日期冒充旧版本首次保存时间。此类缺少可信时间的版本继续受保守保护，供后续 SM-08/10 使用。

迁移不扫描全部历史对象；无法由当前候选证明的旧 MCSF 元数据保持未知。旧 normalized 格式含有自己的元数据，导入写入和 Canonical 激活路径可以从原正文证明恢复。其历史哈希格式是 `{title, archived}`，仍按原形保存，不制造未记录的标签和归档时间。原 normalized 正文读取接口与 MCSF 正文读取边界保持；本项不重编码正文格式。

历史派生需要完整、可证明的 Canonical 基线元数据，缺失时抛共享业务码 `HISTORICAL_METADATA_UNAVAILABLE`；摘要损坏另报 `OBJECT_CORRUPT`。HTTP 仅按错误类型和这两个明确 code 解包最多八层 cause，并检测循环，沿既有协议返回 409。投影异常包装、WAL 与恢复状态机不变；不会按错误文本猜测原因。当前 Maintenance 会话的普通追加使用本次明确输入的元数据，即使旧 head 元数据未知也能生成新版本。当前元数据编辑亦可在旧 head 与当前行脱节时创建明确的新版本，而不覆盖未知旧快照。

数据库 schema 升至 **17**；旧二进制不能直接打开升级后的库。正式发布、备份、停机切换和必要回退由后续集成发布处理。本提交没有部署或对真实库执行迁移。

## 剩余边界

- 无法证明的历史元数据仍未知；不会承诺通过当前值恢复全部历史。其正文与轻量版本关系继续保留。
- 五天保留、对象回收和用户文案属于后续施工项。本项仅提供可靠状态和本地时间，不执行回收。
