# 当前 0.1.5 包的便携验证与文档链接

现有发布脚本已经包含 8 个组件及 `dsh-015-host.js`，便携检查仍要求 7 个组件和旧的 `rc2-host.js`，使正确的当前组合报错。插件 README 还直接复制源码相对链接，安装包中没有相应的根 README 或文档位置。

本次只修改打包与检查脚本，不改运行代码或版本：

- 组件清单以实际 8 个来源路径共享定义；检查每项恰好出现一次，保留原有组件名称和版本核对。
- BUILD-INFO 和发布清单增加当前 0.1.5 宿主的来源文件、构建文件、包内位置及规范化摘要。便携检查同时核对当前源码、已构建文件及包内字节，拒绝缺失、错代宿主和摘要漂移。四个 Adapter worker 均执行隔离的启动协议检查。
- 插件包带入本次规格、UPGRADE 和 RECOVERY，重写包内相对链接。根 README 与历史交付报告链接指向本包精确源码提交；这些网页在提交推送后可访问。避免递归打包整库文档或机器上的历史回执。
- 验证器新增包内 README/docs 本地链接检查。原版本、schema、锁文件、包摘要、协议、Engine 执行和禁用内容扫描保持有效。
- 使用外部插件归档打包时，也核对 README 和随附文档，避免重新引入旧的缺失链接。

针对性验证采用合成的清单、宿主字节与文档链接，覆盖重复/缺失组件、来源及构件篡改、旧宿主误用、换行规范化、链接缺失与越界。新验证测试及既有内嵌插件测试共 10 项通过；源码便携扫描通过，候选包便携检查通过（40 个归档文件）。发布包的实际检查及重新打包回执写到本次交付 artifact 目录；旧包、旧失败结果保留。完整三次重建验证入口会覆盖工作树的默认产物，本次使用其内嵌插件验证函数，并将两次重新打包输出到独立目录比较摘要。
