# 宿主边界与未知结构化数据

## 本次用户确认

来源：本次 Codex 任务用户对上次答复的四项批注及“继续”。

- Maintenance 核心只认识通用端点和规范会话，不认识实例实现、Launcher 或插件名称。
- 实例发现、身份核验、接入安装、Launcher hook、宿主写入权及原生状态由宿主 adapter 负责；Launcher 从 Maintenance 主体解耦。
- 插件专有数据、初始化及会话变化后的业务处理属于插件 adapter。
- 无法识别的结构化数据完整保留，统一打包映射并默认折叠，不直接展示内部结构。

## 实施与验收范围

拆出既有接入实现及依赖，注入核心提供的通用运行记录查询；插件状态维护通过通用生命周期接口注册；未知数据包保留原事件身份、顺序、来源及原始载荷，不把未知数据丢弃或当作已知宿主指令执行。以合成存储、边界检查和展示测试验证。真实宿主写入权、归档恢复、派生续写继续按前次报告跟踪，未经验收不部署。

## 结果

本轮完成源码候选，未更新安装，也未执行真实实例启停或会话写入。整体架构要求仍在实施，不能将下面的局部边界验收等同于整个 Engine 完全解耦。

### 已实现

- 将原 `integrations/service.ts` 中实例发现接入、安装、Launcher hook、目录选择、握手/租约及系统进程证据相关实现迁入 `packages/instance-integration-dsh`。旧 Engine 路径只保留兼容转发；生产装配直接创建 adapter。adapter 查询维护运行记录时调用注入的 `EndpointRecoveryQuery`，不反向导入 Engine。
- 通用 adapter 包加载器迁入 `packages/adapter-host`，消除宿主 adapter 对 Engine 加载实现的依赖。
- 增加通用 `SessionLifecycleAdapter`：核心在规范会话事务内发布归档/删除状态通知。图对象存储、启动时归档对账由知识业务 adapter 实现；adapter 抛错会回滚本次规范元数据变化。图与引用的专属写入限制通过 `validateWrite` 交给各业务 adapter。
- 宿主管理可从装配中关闭，业务 adapter 可不注册。合成测试验证此时仍能保存规范会话和修改归档状态，不生成业务对象。
- 已接纳的 `opaque-unknown` / `other` 事件统一映射为未知数据包，保留原始事件身份、顺序、来源和载荷；规范存储仍保存原事件。阅读器每轮合并为一个默认折叠入口；展开也不请求或展示原始结构。旧阅读列表同样合并为折叠入口。

### 架构审查与下一阶段

1. **遗留业务服务仍待迁移。** `session-graph-service.ts`、`extensions/annotation-sync.ts`、`extensions/gpt-sync.ts` 仍有具体业务处理；`extensions/directory.ts` 存在插件专属目录规则，`session-reader-queries.ts` 仍直接使用具体宿主阅读格式。需逐项迁入业务/格式 adapter，并以小接口注入会话查询、版本和引用解析能力，不能把整个 Engine 作为 adapter 依赖传入。
2. **兼容壳与装配层仍存在。** 本轮移走了具体安装行为，但未清除 Engine 全部旧实例/宿主 API。下一阶段需要收敛为通用端点端口，并保留边界测试；不能仅靠目录重命名宣布完成。
3. **Launcher 生命周期属于宿主接入。** 本轮没有给核心新增停止 Launcher 的责任；真实停止协议也没有因代码迁移而接通。独占写入、flush / drain / release 与取消归档必须由宿主 adapter 提供可核验回执。禁止用直接 shutdown、杀进程或删除锁替代。
4. **真实同步仍未闭环。** 生产装配仍缺少 `withWriteAccess` / 宿主取消归档提供者；对齐保持明确阻止。派生会话序号/引用重映射、只读外部源续写继续跟踪前轮未完成项。
5. **未知数据覆盖边界。** 已验证的是进入规范存储的未知结构化事件。尚不能解析的物理文件格式仍需对应格式 adapter；未知插件的完整外部数据源接入和附件往返尚未验收。本轮未把未知数据变成可执行宿主事件，也未放宽现有文件格式校验。
