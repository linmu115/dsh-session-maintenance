# Codex 项目映射交付收尾

Engine 0.1.20 包含 0.1.19 的项目映射完整实现，以及真实看板验收发现的显示修复：静态阅读目录隐藏空分支，项目内部标识收进详情，同名项目保留区分方式。Maintenance 插件维持 0.2.21；本次收尾不修改插件内容、共享协议或数据库结构。

映射范围取自本地 Codex 项目会话文件夹的显式归属。保存名单后在下次 DSH 实例准备启动时切换；后台继续导入当前生效名单中的变化。当前和下次名单分别展示，未来新增成员自动纳入。名字相同的项目不会合并，也不使用 cwd 代替项目身份。

生产映射已在 rc1 prepare 中验证：33 个目录项目中选择指定的五项，32 个本地来源里有 1 个已由用户删除，继续保留删除状态，因此当前可见 31 个会话。名单外 290 个真源会话移入可恢复删除状态并创建统一恢复点。原有 5635 个版本记录逐项比对不变，旧的已删除会话及所选 DSH 派生会话状态保持。Codex 原始会话仅读取。

## 验证记录

- 映射主体全量测试：193 个文件、742 个测试通过；后补数据库切换策略约束的 15 个测试独立通过。
- 收尾前端的目录裁剪、搜索、同名项目和详情展示测试见 `2026-09-06-dashboard-directory-polish.md`。
- 真实 rc1 启动准备已通过正式生命周期完成，并通过 abort 收尾验证用运行；未替用户启动 DSH 界面。
- 真实数据核验包含 SQLite 完整性、外键、全部既有版本逐项保留、31 个可见会话的显式项目归属、290 条映射移除及对应恢复点。
- 发布过程重新构建并校验打包内容，部署后核对健康检查、看板鉴权、实际服务的静态文件与项目映射状态。部署具体时间、进程和文件校验值记录在发布目录的回执中。

## 回退边界

0.1.20 的前端收尾与 0.1.19 使用相同的 schema 21 和映射策略。回退这次显示修复无需切回旧数据库。回退整批项目映射则应使用本批部署前保存的 schema 20 数据库、内容对象、配置和旧插件版本；不能让旧 schema 20 程序直接打开 schema 21 活跃数据库。
