# Codex 实时更新后的投影恢复

Engine 0.1.22 包含新工作区登记修复和这一关联恢复修复。插件仍为 0.2.21；数据库仍为 schema 21。

## 触发条件

DSH 运行持有启动时的 Codex 镜像，后台观察器随后推进同一镜像的真源版本。Engine 重开并恢复旧运行时，原实现将旧投影与当前最新 head 的事件比较，误报 shorter/diverges from canonical native prefix。恢复中缺少新工作区登记时，此错误会在重开 Engine 后进一步阻塞已有会话的恢复。

## 改动

CanonicalProjectionSource 新增可选的固定版本事件读取接口。SQLite 实现只读取属于指定会话的不可变版本对象，缺失、归属不符或没有对象存储时拒绝恢复，不回退到当前事件索引。

恢复仅对 authority=codex、origin=codex-mirror、尚无本运行提交且当前 head 不等于固定 base 的情况读取旧版本，然后沿用 Adapter 原有的完整前缀校验。DSH 维护侧的提交恢复、过期 WAL 处理与最新 head 均保持原有语义；不回退最新 head，不用投影覆盖当前 Codex 进度。

## 验证

真实 Engine/RC1 集成测试先建立 Codex 投影，再追加并导入 Codex 内容，模拟登记失败和 Engine 重开。修复前稳定复现 canonical native prefix 错误，修复后能恢复失败新会话，原始 inbox 数据保存在 evidence 中且 Codex 来源文件不变。

固定版本读取覆盖旧版本、当前 head 保持、跨会话版本拒绝、缺失版本拒绝和无对象存储拒绝；现有 DSH 过期 WAL 测试保持通过。聚焦 3 文件、11 项通过；最终全量回归 196 文件、772 项通过（226.51 秒），完整构建通过。

## 遗留会话恢复

当前报错会话的 7 条记录已经过逐帧解析验证。维护脚本只补这一条缺失的登记意图，原始压缩文件与数据库先备份，再调用现有未完成登记恢复流程；不移走原始文件来回避恢复检查。恢复后校验既有版本与删除状态保留，并通过一次不启动 DSH 的实例准备核验新本地会话仍在名单应用后存在。
