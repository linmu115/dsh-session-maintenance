# 工作区同步范围 · 2026-09-06

接入管理回答“哪个实例可以与 Maintenance 连接”，同步页回答“哪些工作区被选入范围”。两个设置分别保存，连接一个实例不会自动授权它的所有工作区。

名单存于 Maintenance stateRoot/workspace-sync-policy.json，使用共享写入队列、原子文件替换和乐观 revision。界面展示每个工作区的会话数量、当前选择和未保存变化。保存的工作区名单包含未来新增会话，不需要逐条补选。

本批只有范围配置，nativeWriteEnabled 与 nativeSyncSupported 都为 false。客户端不能通过附加字段打开写入；服务端拒绝未知/已删除工作区和过时的 revision。保存成功提示明确说明尚未执行 Codex 原生回写。

该名单使用当前 Canonical 工作区目录供用户选择；它还不是原生写入的安全授权凭据。未来 writer 必须核对真实 Codex 归属、规范化路径、接入实例、撤销状态，在入队与提交时再次检查，并处理会话移动、并发推进和原生缓存重新加载。不能拿 UI 分组或简单路径前缀直接授权。

DSH 设置栏移除不能代表原生同步能力的旧开关，历史实例/映射标识改为只读。保存只更新扫描范围、备份事务数量和批量安全计划偏好；完整看板入口保留 0.2.19 的全局打开修复。

服务与 HTTP 回归覆盖名单持久化/重启、未来包含标记、并发相同 revision 只有一个成功、未知工作区和伪造 nativeWriteEnabled 拒绝。浏览器合成验收确认勾选与保存后显示未来包含规则和“原生回写尚未生效”。
