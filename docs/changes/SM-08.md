# SM-08：引用安全的只读存储治理计划

日期：2026-09-06。基线 `0dbf921cf0e6aaaee22dfed7df0c1d334ce4205f`，独立树 `maintenance-storage-governance-20260906`。本提交提供 Store 引用清单、登记仓库、纯规划函数及共享 DTO；Engine/HTTP 接线由主协调者串行整合。

本轮明确不实施 SM-10。全部 `session_versions.body_object` 继续保护，包括来源很早、缺少可信保存时间、旧于 120 小时的版本。`firstPersistedAt` 只展示本地保存证据，源 `created_at` 和文件修改时间不替代历史窗口起点。正文对象只有只读孤儿预览，没有治理执行入口。

## 引用与规划

- 清单读取版本/父边、当前双 head、会话固定、平台引用及旧持久化 mirror 引用、Checkpoint、派生、墓碑、projection run/session/operation、WAL 与回执、continuation 源版本和 handoff、adapter evidence、plan/job/transaction/step、Checkpoint 备份关联。
- 父边记录为 `version-metadata`；当前内容、Checkpoint、派生和恢复需要记录为 `version-body`。对象预览展开对应版本的业务保护原因，共享对象按物理对象库和 ID 去重计费。
- Projection close Checkpoint 的 `{run,catalog}` 是运行身份和目录摘要，并非两个版本 ID；未知引用形状阻塞。WAL 未提交、未完成操作保护运行；WAL/回执不一致和未知证据阻塞，不能只信 `closed` 标签。
- 外部库先复制到独立临时快照，再使用 `DatabaseSync(...,{readOnly:true})`，不调用带迁移的开库函数；验证 schema、完整性、外键和所有引用表。复制前后检查来源身份、长度和时间，存在 WAL/SHM/journal 时阻塞；避免 SQLite 只读连接在来源目录创建伴随文件。保留外部库的全部正文、handoff 和 evidence 共享对象受保护。未知/损坏/缺失库或未登记候选库阻塞；没有零引用兜底。
- 登记根包含实路径、设备/inode/创建时间身份。路径分量拒绝 symlink/junction、越界和 hard link。登记资源不得重叠，不允许把整个 state/object root 当作治理资源。
- `asOf`、策略、完整引用表修订、根/来源登记、对象列表、资源/WAL/manifest 证据指纹固定进入计划 ID；复核任何差异返回 `PLAN_STALE`。旧 catalog journal 不承担全部引用修订证明。
- `ZstdContentObjectStore.collect({dryRun:true})` 复用现有 GC 分类，前置受控路径清单；不读取压缩正文。文件字节指压缩实体长度，不是展开正文长度。存在阻塞时候选不可执行。

## 迁移与接口

迁移 019 新增 `retention_roots`、`retention_sources`、`retention_resources`，没有自动登记/猜测真实目录，没有改写版本和正文。018 未使用，由协调者保留序号。升级后的库不能交回只支持 schema 17 的旧二进制。

共享 DTO 位于 `packages/contracts/src/retention.ts`。Store 公共接口为 `RetentionRepository.registerRoot/registerSource/registerResource/capture`、`planRetention`、`assertRetentionPlanCurrent`。所有登记写入由 Engine 置于 SM-05 的写入协调作用域；只读 capture 本身不迁移、不登记、不删除。默认初始空登记返回阻塞状态。

## 验证

仅使用名称含 `SYNTHETIC` 的临时夹具；没有打开真实 state/Home，没有实际 GC。新增 6 项预览测试及 1 项迁移失败/重试测试。Store 全套加 Canonical 激活集成回归覆盖历史元数据、版本身份/正文、schema 迁移和已有 GC；旧“未来 schema=18”用例随迁移更改为 999 后聚焦重跑通过。20 个文件共 45 项验证用例均获得通过结果（原全套 19 文件 44 项，其中一项旧预期修正后与新增迁移测试一起重跑）。Store 类型检查与 `git diff --check` 通过。

## 明确边界

本提交没有线上启用和目录删除。run/cache/backup 的完成/容量规则先体现在规划中，显式隔离、宽限、恢复及最终释放属于 SM-09。未知资源和来源保持受阻，需登记真实所有权与验证证据；旧外部 schema 支持明确验证的 16/17/19/20，schema 16 缺少元数据快照时本地保存时间明确未知，其他版本阻塞。全部外部 writer 是否遵守同一协调协议由 Engine 组装证明，SQLite 锁或一次只读扫描不足以授权物理操作。后续 SM-09 增量补充静态平铺库登记、按日志实际成员位置读取中断中的引用，以及所有对象根与治理资源的双向边界复核。
