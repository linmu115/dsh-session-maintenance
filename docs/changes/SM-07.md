# SM-07 — Maintenance registers actions with the unified menu

Maintenance previously installed its own bubbling `contextmenu` listener while
SCM captured the same event. Its entries could be hidden by the host. Maintenance
now registers its existing nine actions with SCM menu API 1 (deployed in SCM
0.3.2). It creates no competing menu or document listener.

The consumer listens before discovering the host, supports either loading order,
ignores stale events, re-registers after host replacement, and unregisters on
disposal. Optional legacy row decoration no longer gates the menu API. The host
owns row/keyboard selection and feedback; Maintenance rechecks the current
native session ID against its session snapshot immediately before dispatch.
Titles never identify targets, and candidate deletion remains a preview action.
The scan label now accurately describes its existing instance-wide scope.

Host cancellation and consumer disposal reach same-origin fetch and suppress
late dashboard windows. Cancellation does not claim to undo a server operation
already accepted. Active errors are returned to SCM for visible feedback.
Settings and optional sidebar dashboard entry points remain available without
SCM. No capability token is exposed to the browser.

Validation: contracts build and Maintenance typecheck passed; 25 tests across
menu consumer, restricted proxy, settings and UI contract passed. The ten
consumer tests cover late/repeated registration, unavailable host, same-title
selection changes, missing rows, pending action exclusion, cancellation and
late results. SCM's existing selection/keyboard tests are run in final combined
validation: all 34 host tests passed. Dashboard integration now shows durable
import progress/cancellation independently of projection diagnostics, translates
runtime phases, and preserves unknown/corrupt version metadata warnings. The
shared contract, client and Engine routes are connected in the selected batch.

No Engine schema or native session format change. Source baseline `0dbf921`;
current production remains Engine 0.1.15 / Maintenance 0.2.17 / SCM 0.3.2 until a
separately recorded activation. Browser acceptance is performed by the user.
