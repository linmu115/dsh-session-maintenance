# SM-09-flat：既有平铺恢复库治理与引用边界复核

日期：2026-09-06。承接 SM-08 `950bb66` 与 SM-09 目录治理 `8b20ed0`，依赖 SM-05 `1668714`。本增量不增加迁移，逐成员状态保存在迁移 020 的批次 JSON 内；共享 DTO 增加可选成员清单及守卫证据，保留已有目录批次的兼容读取。

## 行为与接线

`RetentionService.registerFlatCandidate(sourceId)` 接受已登记、保留的非 active candidate/backup source，返回验证后的 `RetentionResource`。共享输入 schema 为 `retentionFlatCandidateRequestSchema`，参数形状为 `{sourceId}`；主协调者负责 `POST /v1/retention/flat-candidates`、认证、客户端与界面。`registry(): RetentionRegistry` 正式使用共享 DTO。

登记只接受主 SQLite 文件及其 `.manifest.json`，核对 manifest 路径与主文件摘要，再验证 SQLite 完整性、外键和所有正文、handoff、adapter evidence 的可恢复性。明确拒绝 active 库、任何 WAL/SHM/journal 或未知伴随文件；验证失败不移动文件，不产生可执行资格。未登记治理的旧恢复库及伴随文件以受保护的 database 项计费；登记后与资源字节去重，四份已验证恢复点遵守每组保留最近三份规则。

外部来源使用复制后的临时 SQLite 快照，复制前后核对文件身份、长度和修改证据，避免只读 SQLite 连接在来源目录生成 WAL/SHM。此稳定读取不等于写入排他：任何 retained source 位于当前 SM-05 owner 根外时，预览仍读取并保留引用，但执行阻塞。不会把未知外部 writer 当作静态来源。

## 中断、恢复和安全边界

批次先记录主库和 manifest 的原路径、隔离路径、身份、长度及内容清单，再逐成员移动并登记进度。主库已移动而 manifest 尚未移动时，引用清单根据活动 journal 的实际位置读取同一 source；原/新位置必须恰有一个且文件身份匹配。隔离完成仍保留库引用，恢复完成原样还原两个文件和 source 指针。

释放前再次验证宽限、当前引用、保留数量、登记和其他资源指纹；处理始终位于同一 SM-05 排他窗口。部分释放重启后只继续已记录成员，不删除未知新增文件；守卫变化停止重试。进入最终释放后不承诺恢复。批次重试按持久状态进行，不需要旧 Engine 的内存计划。

独立复核发现并修复三项边界：对象 namespace 与资源必须双向不重叠，检查包含没有 source 指向的 objects/state 根；登记完整路径只覆盖自身子树，不能用 `group/known` 隐去 `group/unknown`；每次 capture 和实体操作动态复核边界，防止先登记缓存、后引入共享对象库绕过保护。生产 retention 模块统一整理为两空格、多行格式。

## 验证

仅运行带 SYNTHETIC 标记的临时夹具，不接触真实 state/Home、候选文件和对象库；没有执行真实回收。新增 6 项平铺恢复测试、3 项边界测试，覆盖四份实际 SQLite 备份、原字节恢复、隔离中断时引用、逐成员恢复中断、WAL/未知伴随文件、部分释放重试、对象 namespace 反向登记、嵌套未知目录和外部 owner 边界。与原有预览、目录治理、迁移测试合计 5 个文件 28 项聚焦测试。

SM-05 审查代理在独立树额外运行 10 项安全复核，与本项四组测试组合为 36/36 通过；包括真正关闭并重开数据库及 owner 后继续恢复/释放、部分释放后新未知文件拒绝继续，以及半移动/半恢复时引用仍受保护。验证期间关键生产文件摘要未变化。最终格式整理后在本树再次运行聚焦测试，5 文件 28/28 通过（51.28 秒），全仓类型检查通过；完整构建在平铺功能完成后已通过，最终集成全套与打包由主协调者执行。

## 限制

未验证的 manifest、未知 schema、活动或不完整的 SQLite 伴随文件、根外 writer 所有权、路径链接及身份变化均保守阻塞。文件系统与 SQLite 之间没有跨介质原子提交，journal 负责已记录文件移动/释放的对账；无法证明目录或文件身份时保持阻塞并要求审查。没有定时自动删除。SM-10 明确排除，全部现有版本正文继续保护，五天历史裁剪未生效。
