## 看板与 API 接入

运行中心分别显示 Codex 导入任务和投影运行状态。投影诊断加载或失败不隐藏独立的导入入口。取消显示为取消，缺失或损坏的历史元数据保持明确提示，零待提交项不会被解释为恢复已完成。

新增“存储治理”页面：初次打开只读预览；可显式识别已有副本、登记数据库与正文库对应关系、验证副本、隔离、恢复和最终释放。发生部分移动错误后重新加载持久化批次，继续隔离/恢复/释放入口仍可见。请求复用已有 bearer 或 UI session / Origin / CSRF 鉴权，严格解析输入，不接收可覆盖计划目标的路径参数。

默认策略为普通完成运行副本保留 48 小时，完成恢复的运行证据保留 120 小时，每组保留最近 3 份有效自动备份，可重建缓存目标 1 GiB，隔离宽限期 48 小时。固定、活动、恢复依赖和未知实体可超过这些容量目标；系统展示原因，不为达到目标而强制删除。

缓存排序使用登记时记录的时间与随后可验证的刷新时间，不根据文件修改时间猜测使用情况；纯读取命中暂不单独记录，因此不宣称完整的访问 LRU。活动及保留运行对缓存的依赖始终优先保护。

同一路径重建的缓存使用新的目录身份登记，旧批次保持原身份；旧恢复不会覆盖新缓存，旧隔离副本释放后新缓存仍可独立治理。登记、再生、容量排序、恢复和 API 的最终组合聚焦回归为 5 文件 26 项全部通过，包含刷新排序的只读性断言；全仓与打包验证另见交付台账。

平铺候选库要求登记的非当前数据库、与其匹配的清单、可恢复的共享正文以及静止证据。WAL/SHM/journal 或未知伴随文件均阻止治理。数据库和清单各自记账；隔离期间备份引用继续保护正文。外部数据库可以登记为引用源；缺少覆盖整个操作窗口的外部所有权证明时，执行被阻止。

共享正文目录在登记和每次执行前双向排除，不能先登记缓存再通过另一处登记绕过保护。未知嵌套兄弟目录按完整路径识别。当前批次没有自动清理定时器，也没有任何正文删除入口。

## 架构关系

UI、CLI 和导入脚本调用 Engine 服务，写入协调器控制排队和所有权；导入服务、生命周期和副本治理共用该边界。格式解释继续留在 Adapter。副本治理读取持久化的运行完成与引用证据，不拥有另一套运行状态机。Launcher 只管理通用进程生命周期，调用 Provider，不承担扫描、会话 SQL 或保留策略。

## 性能证据

在 5,000 事件合成会话上连续追加 12 个事件：索引从 60,090 次插入和 60,078 次删除降为 12 次插入、零删除；提交中位耗时从 1,093.93 ms 降为 471.26 ms。其他施工代理同时运行，因此耗时是本机测量，不是性能承诺；正文新增存储量相同。详见 [SM-11 报告](SM-11.md) 和 [原始数据](../validation/2026-09-06-sm11-index-benchmark.json)。
