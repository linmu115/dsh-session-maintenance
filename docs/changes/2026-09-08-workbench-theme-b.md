# Maintenance WebUI：B「清晰工作台」

用户选择浅色为主、接近 DSH 的 B 方案。本次将该方案接入真实 Dashboard，交付 Dashboard 0.1.1，随 Engine 0.1.24 发行；Maintenance 插件保持 0.2.21。

## 页面变化

- 顶部品牌栏高 54px，左侧功能栏宽 64px，保留会话、同步、恢复点、存储空间、设置五个入口，并为当前入口提供 aria-current。
- 冷灰页面背景、白色内容面板、黑白主按钮、低饱和蓝色选中态。状态颜色独立保留成功、提示、警告和错误语义。
- 会话页使用 240px 工作区目录与静态 Markdown 阅读区；中等窗口使用 224px 目录。收紧目录标题、来源和日期间距，长标题保留完整提示。
- 760px 以下改用横向导航与可展开工作区目录；选择会话后收起目录。阅读区继续只展示已保存内容。
- 同步、恢复点、存储及设置统一边框、文字、卡片和表单样式；修正恢复点两列卡片顶部错位。
- 存储表格增加行列间距和可聚焦的横向滚动容器；小屏保留全部列，登记表单改为单列。

## 外观设置

右上角可选择浅色、深色或跟随系统。默认浅色，偏好保存在当前浏览器的 `dsh-maintenance.appearance`；不调用 Engine 配置接口。页面连接前应用已有偏好，避免重新加载时闪成浅色。存储受限或已有值无效时仍可打开页面和切换外观。

所有颜色集中到共享 UI 的语义变量，通过 `color-scheme` 与 `light-dark()` 适配明暗。保留键盘焦点、粗指针点击区域及减少动态效果偏好。

## 数据与集成边界

不修改 Engine 后端逻辑、Adapter、Launcher 协议、DSH 插件、项目映射名单、同步范围或恢复与回收规则。会话页没有新增输入或正文改写能力。此次版本递增用于标识随包交付的 Dashboard。

浏览器验收使用 `apps/dashboard/test/fixtures/workbench-preview.tsx`：直接渲染真实 DashboardApp，提供合成的工作区、会话、Markdown、项目映射、恢复点、存储和接入信息。所有数据写操作拒绝，未导入真实客户端。该入口位于 test，不进入生产构建。

## 验证

- 先验证新增外观测试 4 项和目录展开测试 1 项在实现前失败，再完成实现。
- 最终 Dashboard 与共享 UI：14 个测试文件、52 项测试通过，覆盖外观记忆、受限存储、目录展开与选会话、既有读取和维护页面行为。
- 共享 UI 构建、Dashboard 类型检查和生产构建通过。
- 浏览器检查五个主页面、明暗切换、刷新后保留选择、长标题及 Markdown 列表/表格/代码，控制台无 warning/error。
- 检查 1280、1024、736、360、320px 窗口。320px 下页面 scrollWidth 与 clientWidth 均为 305px（另有 15px 纵向滚动条），没有页面横向溢出；存储表格在自身容器内滚动，键盘可以聚焦。
- 恢复点两列卡片的顶部坐标一致。手机选择会话后目录收起，正文正常切换。
- 样式解析无 warning；24 组明暗文字与背景对比度检查最低 5.12:1。

## 发布方式

本批只需更新 Dashboard。为保留当前正在运行的 DSH 会话，发布时先核对新旧 Engine 主程序、Adapter worker 及插件摘要；只有后端字节一致才进行页面资源更新。

部署保留旧入口和旧哈希资源，先放入新资源，再替换 index.html。已打开的旧页面仍能加载其原有延迟模块；刷新后进入 B 方案。Launcher 后续启动指向完整的新发行目录。实际产物摘要、原文件备份、运行 PID 和验证结果记入本机发行目录的部署回执，不将未重启的旧进程描述为新 Engine 进程。

回退可先恢复已备份的旧 index.html 和 Launcher 配置；因为旧资源仍保留，不需要改动会话库或终止当前运行。
