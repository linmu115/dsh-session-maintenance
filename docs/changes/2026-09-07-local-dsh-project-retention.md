# Preserve live local DSH project sessions

Project mapping cleanup previously retained Maintenance-native sessions only when their canonical project was in the selected Codex project set. A new DSH local project therefore lost its active sessions on the next mapping activation, even though Codex selection was unrelated to that project's ownership.

The keep set now also protects active `maintenance-native` sessions with Maintenance authority inside projects whose `source_platform` is `maintenance`. Both the logical session deletion field and any unresolved tombstone must indicate that the session is active. Protection follows only active Maintenance `codex-derived` descendants through valid DSH-continuation edges whose base version belongs to the parent. It does not cross a deleted intermediate session.

Preservation and automatic restoration use separate sets. The original explicitly selected Codex set still controls restoration of mapping removals, including existing DSH branches. Local protection prevents deletion of current work but cannot restore previously removed local sessions, manually deleted records, or deleted descendants. Project membership alone never protects a Codex mirror or a record with mismatched authority/origin. No policy keys or Codex source files change.

Two new synthetic regressions failed before the implementation change because live local sessions were tombstoned. After the fix, the mapping and manual-restoration suites passed 12 tests. Coverage includes repeated empty selection, local descendant chains, deleted roots/children, disconnected descendants, misleading project membership, unchanged canonical heads, untouched Codex fixture bytes, and the existing explicit Codex removal/restoration behavior. The selected Codex descendant test also checks deselection and reselection of all three generations.

Read-only offline audit: `canonical-reseed.ts` creates a fresh candidate from only the explicit `retainedDshSessionIds`; it does not carry forward active canonical-native sessions from the current database. Its current policy inheritance and generic activation policy equality guard do not prove native-content completeness. Thus a later use of the Alpha2 reseed command can omit newly created DSH content even when the Codex policy is identical. This specialized offline path was not changed in this fix. A future safe extension should either carry forward the retained native canonical graph or explicitly reject activation of a reseed candidate missing active native heads; automatically importing every old native file would risk restoring deliberately deleted sessions.

Conversation topology repair starts with a full database backup and retires only Codex mirrors, preserving independent native sessions. Candidate retention governance validates complete database/object references and protects all version bodies; it does not filter sessions by project ownership. This change does not modify Broker/resolver behavior, deployment, versions, or real runtime data.
