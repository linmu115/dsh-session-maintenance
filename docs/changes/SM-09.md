# SM-09：运行、缓存和备份的显式治理

日期：2026-09-06。独立树 `maintenance-storage-governance-20260906`，承接 SM-08 `950bb66`；集成依赖 SM-05 `1668714` 的共享写入协调协议。Engine/HTTP/界面最终接线由主协调者提交。

## 已实现行为

`RetentionService` 提供 `preview/execute/restore/purge/listBatches/registry/registerRoot/registerSource/registerResource/verify/discover`。预览只读；最近 64 份计划保留在 Engine 内存，重启需要新预览，已经开始的批次通过持久化计划恢复。没有定时或默认自动回收，执行能力默认关闭，由已接齐 SM-05 writer 的 Engine 组装显式开启。

- finished run 必须由数据库状态、收尾 Checkpoint、恢复描述符、WAL/回执共同证明；普通结束至少 48 小时，恢复完成至少 120 小时。运行活跃、未决、未提交 WAL、未完成 operation 都保护实体。
- 保留的稀疏运行（包括已关闭但目录仍保留的运行）保护其 base cache。空闲缓存按最近使用时间和 1 GiB 目标规划，受保护数据超过目标时只报告，不强删。
- 自动备份每组保留最近 3 份有效记录；手动固定和 Checkpoint/事务恢复依赖额外保护。有效性需显式验证 manifest、事务回执和每个必需备份对象的摘要/长度。已登记目录式候选库验证 SQLite/外键、manifest 与全部共享正文/handoff/evidence 的可恢复性。
- 已知 run/cache/transaction-backup 通过产物证据发现并登记；未知目录保持受保护/受阻。外部恢复库显式登记对象库归属，不以目录名猜测。`bindActiveSource` 支持选择复制后的候选库，将旧 active 保留为 backup source，不遗失旧库引用。
- schema 16 回退库按已知引用表只读解析，缺少快照时本地保存时间明确为 null；未知 schema 仍阻塞。SM-08 的版本/对象关联改为 Map 索引，排序摘要预先计算；新增 5,000 个版本/对象、10,000 条引用的规划测试，避免立方级扫描。

## 执行、宽限与中断

迁移 020 新增 `retention_batches`。批次先持久化 exact file 清单和原/隔离路径，再在同一 `MaintenanceWriteScope.run` 内重新确认根与实体身份后移位到登记根内的 `.retention-quarantine`。来源指针、资源状态与 journal 一起提交；隔离的候选库仍 retained，正文引用继续保护。

48 小时宽限期后，显式 `purge` 再次读取当前引用、登记、其他资源和备份保留数量。数据库 journal 提交之后直到最后一个实体操作都不释放写入协调窗口。最终删除只使用已记录的文件清单，每个实体再校验身份；不递归清除执行期间出现的未知文件。中断后按 exact 清单继续，已经删除的文件不重复计费；新增引用/登记变化时停止并要求恢复审查。

恢复核查当前引用、根/文件身份和原路径占用，然后原样移回；不会覆盖复用的原路径。隔离或恢复移动之后、journal 提交之前崩溃，通过两个位置和 exact 身份重新对账。进入最终释放后不承诺可恢复。路径拒绝符号链接、junction、hard link 和根替换；外部治理根暂不借用当前 stateRoot 的 owner，仍只作为只读引用来源。
