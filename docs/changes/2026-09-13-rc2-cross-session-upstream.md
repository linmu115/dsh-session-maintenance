# RC2 副本：P1 跨会话上游引用

日期：2026-09-13。开发目标：Launcher 中的 `0.1.5-rc.2 副本`，profile `web`。

本次实现已确认设计的 P1：在一条完成的 AI 回复中选取重点文字，选择另一个工作区/会话，进入该会话的完整页面并添加引用气泡。发送后，AI 可通过工具读取来源从开始到所选回复结束的历史。来源后续新增的消息不会进入此引用。

依据：[设计和功能需求](../superpowers/specs/2026-09-10-session-context-graph-requirements.md)、[插件改动清单](../superpowers/specs/2026-09-10-session-context-graph-plugin-changes.md)。这些文档保留原审批阶段状态；本报告记录实际首期交付，不将 P2/P3 标为完成。

## 行为与数据

1. 选择器先列工作区，再按需加载会话。每页 50 条元数据；目录来自当前实例已准备的原生空间映射和项目归属，不以正文是否在内存为条件。
2. 来源为已完成的 AI 回复。流式未完成或无法确认完成事件时明确拒绝，用户在回复完成后重试；本版没有“等待流式完成”的悬挂草稿。
3. 导航到目标完整页并等待目标原生输入栏挂载后，才向该目标添加气泡。不会替换输入框文本或附件，也不会自动发送。失败可在选择器中重试；同一操作使用稳定身份去重。
4. 初始请求包含有界重点选文、来源说明与引用身份。重点选文最多 16,000 字符，并受现有请求预算约束，不自动展开全量历史。
5. 固定范围记录原有逻辑会话 ID、既有不可变版本 ID、完成事件 ID 和摘要。RC2 Adapter 验证原生回复位置与转换回执；格式证据由已有 Adapter 读取能力还原。不会给每次引用新增整份会话备份。
6. 引用保存在统一扩展存储的 `annotation-upstream` 命名空间。对象包含选文、来源/目标身份、固定上限与 pending/sent/revoked 状态；原生历史保存原本真实发生的消息和工具记录。
7. 目标实际消息持久化后绑定 `targetMessageId`。取消草稿、删除引用与失败重试复用 Annotation 的持久 outbox；解除引用不删除来源会话或笔记。
8. 已提交引用在目标后续轮次继续可用，直到解除或来源不可用。新建关系应重新从来源选择；复制旧关系到另一目标或通过继承的快照获得其它目标的读取权会被拒绝。
9. 来源追加、重生成不会改变已保存范围。原版本清理、删除或摘要无法校验时明确不可用，不回退到最新版本、不永久钉住所有源版本。

## 按需工具与限制

`dsh_upstream_read` 读取固定范围，`dsh_upstream_search` 在该范围中查找。AI 只提供引用 ID、游标及搜索词；实例、目标、执行轮次和预算由可信宿主确定。草稿、其它目标和已解除引用均不能读取。

- 默认单页最多 8,000 序列化 UTF-8 字节；后端协议硬上限 16,000。最多 20 个结果，超长单条内容可分段翻页。
- 每个目标执行轮次默认总上限 24,000 字节，所有引用、读取和搜索共享。后端协议上限 64,000，但宿主不会向模型提供提高预算的参数。
- 宿主同时计算模型窗口、当前消息、工具说明、输出预留和额外余量。按保守的字节预算收紧可用量，并限制为窗口的 20%。并发调用先占预算再读取；更换游标或重复请求不会恢复额度。
- Codex 执行器从当前绑定的原生 thread/turn 用量通知提供窗口、输入和输出 token 数；Core 使用此真实内层额度，而不是猜测外层 DSH 窗口。工具使用现有 Runtime Support 的可拔插导出接口，卸载时撤销。
- 无法确定模型窗口，或普通 DSH 请求已有多媒体内容的成本无法保守估算时，不自动展开上游；初始有界引用仍遵守原提交预算。Codex 用量尚未到达时明确不可用，通知到达后可重试，结束后旧用量失效。这些参数是本地首版策略，不声称适用于所有模型的精确 token 计量。
- 读取从截止位置向上分页；搜索结果附带可用于正文继续读取的游标。结果返回版本、截止位置、剩余额度和是否还有内容。工具调用记录反映实际读取范围。
- 不递归展开来源中的其它引用，不自动生成摘要，不把来源权限、模型路由或系统提示词复制给目标。

## 接入和兼容

Maintenance profile 在原有 `extensionPlugins` 中增加：

```json
{"namespace":"annotation-upstream","pluginVersion":"0.3.12-rc2.1","writerId":"dsh-annotation-core"}
```

它在当前实例启用扩展面板及宿主 `maintenanceSessionContext` 能力。缺少该能力时明确报不可用，不走私有历史目录读取或另一套连接。Engine HTTP 请求仍使用已有本地认证；凭据和运行 ID 不下放到客户端或模型参数。

Engine 保留已验证的旧 RC2 插件/回执组合，同时加入新组合的精确白名单，逐文件摘要、实际宿主闭包与实例身份验证继续执行。因此共享服务升级不要求重写主 RC2 profile。

## 验证范围

自动检查使用合成数据与标记的临时目录：原生和导入格式的截止映射；固定版本；未来消息排除；跨目标拒绝；扩展写入幂等；预算/UTF-8 分页/搜索继续读取；保存、解除与断线重试；选择器分页和目标挂载；现有注释与侧聊回归。三个功能项目均执行类型检查和构建。

安装回执与实际测试输出保存在本次独立 artifacts 目录。自动测试及宿主探针不等同于用户在副本中完成真实模型与 UI 验收。

## 副本验收步骤

1. 从 Launcher 打开 `0.1.5-rc.2 副本`。准备来源 X 和目标 Y；Y 留一些草稿文字和附件。
2. 在 X 已完成的较早回答中选一段，点击“跨会话引用”。滚动工作区/会话列表选择 Y。确认进入 Y 完整页面、出现上游气泡，原草稿和附件保留且未发送。
3. 让 Y 查找来源较早内容并发送。检查 AI 使用上游读取/搜索工具；初始消息没有整段上游全文。
4. 在 X 继续新增一条带独有关键词的回复。回到 Y 搜索该词；原引用不应读到截止位置之后的新增内容。
5. 读取超长回复并连续翻页；确认到预算后明确停止。删除关系后再次请求读取，应报告不可用且 X 仍然存在。
6. 重启副本后检查已提交引用与解除状态；选择超过原预载阈值的冷会话验证正常打开。

上述交互验收由用户执行。首次交付若出现缺陷，应记录操作与引用 ID，沿用本分支修复，不将范围扩展到 P2/P3 来绕开 P1 问题。
