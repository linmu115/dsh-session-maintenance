## 问题与最终行为

此前 HTTP 文件直接读取 canonical 表并编排元数据修改、删除、恢复、删除前 Checkpoint 与投影模式调整。投影删除还依赖路由在身份解析和修改之间不能插入 `await`，业务正确性容易随 HTTP 重构被破坏。

本次把实际业务迁入 `SessionMaintenanceCommands`，把工作区目录、项目目录、详情和血缘、历史元数据状态、最近删除、运行中心及精确运行/native 身份读取迁入 `SessionMaintenanceQueries`。两者由 Engine 构造并直接提供给路由使用，没有增加仅转发方法的 Engine 包装层。共享请求及结果继续使用 contracts 现有 DTO，没有新建重复 DTO。

`deleteProjectedSession(runId, nativeSessionId)` 在异步日志启动完成后，以单个同步 `BEGIN IMMEDIATE` 事务执行以下步骤：重新解析精确身份、验证运行状态与 canonical 会话、读取当前 head 与待提交数量、建立或复用 Checkpoint 和墓碑、修改工作区成员及投影模式、形成删除回执，然后提交。身份解析与删除之间没有异步间隙，且命令和查询必须使用同一个数据库连接。逻辑 ID 删除复用同一事务内删除实现。

元数据修改直接复用 SM-02 的 `advanceCanonicalSessionMetadata`，其 SAVEPOINT 包含在命令外层事务中，与成员调整一起成功或回滚。恢复的会话验证也移入其修改事务。目录及详情查询保持已有排序、项目/工作区分组、血缘与历史元数据不可用语义。

保留的行为包括：同名会话按精确身份区分；关闭运行和缺失映射拒绝删除；重复删除复用 Checkpoint；待提交写入返回 `pending-delete` 并进入 `recovery-only`；排空后隐藏；恢复按 authority 返回 `codex-read-until-write` 或 `maintenance-write`；删除前 Checkpoint 指向当时的 head。删除保留窗口仍为原有 30 天，Checkpoint ID 和创建者规则不变。手动 Checkpoint 原有 Engine / WriteService / CheckpointService 入口已是业务服务，本次保持该调用链。

HTTP 的会话路由现在只解析输入、调用命令/查询并映射响应；认证检查保留。`http/dashboard.ts` 只保留静态资产服务和路径常量；`http/projection-identity.ts` 被移除，其实现及测试入口迁至查询服务。Adapter 注册、选择及投影 source 组装块未修改。
