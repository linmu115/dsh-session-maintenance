# DSH 原生会话占位标题修复

## 原因与改动

测试实例中两条有对话的会话，在第一条用户消息之前的宿主对齐曾写入 `session/title`，其值恰好是原生会话 ID。DSH 的首消息标题提供方看到已有标题后不再自动生成回退或模型标题。Maintenance 当时也把该 ID 保存成了真源标题，因此两个界面都只显示 ID。历史写回备份证明，写回前其中一条会话只有三个设置事件，没有标题；旧写回回执则在第 4 个位置生成了 ID 标题。

DSH 0.1.5 adapter 现在统一识别原生 ID、逻辑 ID 和宿主登记时的 `DSH session <ID>` 占位名。占位名不再转成新的原生标题事件；DSH 宿主投影缓存也不再把它当作已有标题。真实的手动改名和 Codex 镜像标题仍按原顺序投影。Maintenance 核心没有加入任何 DSH 标题格式判断。

对已经写入的标题事件，不改写会话历史或回执。本轮通过 DSH 正式重命名入口，按首条用户请求为两条有消息的测试会话恢复可读标题；新标题随后由现有双向同步进入 Maintenance 真源。另有三条空白测试会话在真源中只有 ID 占位名，其中两条旧日志含历史占位标题事件；它们没有用户消息，因而没有可恢复的请求标题，本轮没有猜测名称或删除会话。新建的空白会话经更新后的对齐仍未被写入 ID 标题事件。
