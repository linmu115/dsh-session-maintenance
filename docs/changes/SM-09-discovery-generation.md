# SM-09：缓存重建代际登记修正

日期：2026-09-06。承接平铺治理 `f08bf83`，不增加 API 或迁移。

发现资源的 ID 原来只包含登记根、相对路径和 producer owner。旧缓存隔离或释放后，同 adapter/config/path/cacheKey 的新缓存会撞到旧 ID，被资源状态守卫拒绝。现在 ID 额外包含已验证目录的 dev/ino/birthtime 物理身份；解析 producer 证据前后再次核对身份。普通内容或 mtime 更新不改变代际，旧资源和批次保持原身份，不复绑定。

完整再生测试同时发现两处既有执行限制，本提交一并做最小修正：仅在新缓存已按不同物理代际正式登记、旧隔离目录身份匹配时允许释放旧缓存；恢复仍拒绝覆盖原路径。多层缓存移位后的空祖先目录按 journal 原路径递归检查，仅允许遍历，不将祖先或未知兄弟当作已登记资源。

新增三项 SYNTHETIC 聚焦回归：隔离期间同路径重建可登记新 ID、旧恢复拒绝覆盖、宽限后只释放旧缓存、新缓存可独立隔离恢复；旧代际已释放后同路径重建仍可登记和治理；journal 祖先旁的未知兄弟仍阻塞，移除该空未知夹具后才允许释放。没有操作真实目录，没有改变历史正文保护规则。

验证：再生 3 项、目录治理 9 项、安全边界 3 项、平铺恢复 6 项，共 4 文件 21 个不同用例通过；Store 类型检查及提交差异检查通过。临时使用集成树的 SM-05 合同与协调器验证，未将这些依赖重复纳入本提交。
