# 会话标题持久化与重启恢复

日期：2026-09-15。Engine 0.1.33-rc2.22 / Maintenance 插件 0.2.26-rc2.18 / DSH 0.1.5 Adapter 0.1.2。

跨会话选择器已经能够显示 DSH 的可读标题，但旧的登记名称还留在 Maintenance 中。启动时把登记名称无条件写入标题缓存，使原生日志中的真实名称在重启后被覆盖。

## 变更

- DSH 格式解释仍由 Adapter 负责。从官方 `session/title` 事件提取有效标题，作为 append 元数据提交给 Maintenance；普通后续增量不会把名称改回旧值。
- 名称提交取得持久回执、但会话映射保存失败时，重试使用该回执对应的已持久化 WAL 操作恢复标题。重放旧回执不会覆盖较新标题。
- 物化时从已经恢复的完整事件前缀生成标题及截止证明，不额外扫描磁盘历史。不含原生标题的 Codex 镜像使用 canonical 名称。
- 持久缓存的全量构建、增量更新和临时会话初始化都使用 Adapter 已返回的标题作为运行态名称；旧记录恢复后的普通追加也不会再带回登记名称。
- 启动缓存遵守当前原生版本。在完整物化模式下，已验证前缀替换旧版本缓存，包括恢复较短历史后的越界缓存；临时覆盖层保留可代表后续增量的有效缓存。没有前缀证明的登记名称不能冒充已经折叠到日志末尾。
- Adapter manifest 的版本升到 0.1.2，让旧缓存即使 canonical head 未变化也会重物化一次。缓存 key 和目录保持一致；后续无变化启动继续复用，不增加每次打开会话的全文读取。

六个扩展命名空间、Core 0.3.12-rc2.12、ThoughtDAG 0.4.14-rc2.9 和其他插件版本保持不变；数据库 schema 仍为 24。不修改原始 Codex 会话、既有固定版本引用或笔记内容。

## 验证范围

使用合成会话检查旧登记名称恢复、合法重命名、后续普通 append、持久回执后的映射故障及重试、旧回执重放、官方事件边界、Codex 名称回退、同 head 的旧缓存升级和再次启动复用。运行副本是否安装成功以及真实原生日志标题一致性由独立部署验收记录确认。

最终结果：完整工作区构建通过；标题、官方 V3 回放、持久缓存、增量提交和插件缓存回归共 32 项通过，当前 Engine/插件真实发现与接入证明的 2 项测试通过，共 34 项。插件独立类型检查通过。首次旧缓存升级保持同 key 和目录，后续无变化重启没有再次加载 canonical 会话历史；缓存增量改名和恢复更短版本另有覆盖。
