# Dedicated canonical V3 materialization and attachments

The original RC2 candidate rejected every nonempty portable user history because RC1's generated user-before-step chronology could not pass the official V3 migration. Its portable attachment conversion also replaced all image references with labels. A separate source-export digest/native-source fix is committed by Main in 6f65505; this change consumes that contract without changing canonical or projection digests.

The new portable builder writes V3 directly, with a monotonically ordered receipt for each source event and a complete reverse restoration check. Log-only canonical reasoning and other information remain in their original archive positions and never enter model content. Consecutive model fragments retain ordered blocks; separated assistant fragments use distinct native steps so RC2 UI does not overwrite an earlier message. Tools retain exact IDs, names, arguments and result text; ambiguous/missing pairs and aliases fail. Original IDs map to resulting message anchors.

Images and files are typed, content-addressed resources. Original bytes and data URIs remain recoverable; no lossy transcoding or label substitution occurs. The codec resource hook validates inventory digests, publishes immutable objects under the owned native space, and rechecks retained resources before readiness. The provider points only RC2 attachment-local at that same space. Old adapters, plugins, real canonical state and old homes are not edited.

Validation: 28 tests across the combined V3/source/provider/attestation set pass. The 12 existing provider tests and 6 native-space tests (including 205 retained sessions and resource failure before readiness) also pass. Engine typecheck and recursive dependency build pass. Real 38 live canonical heads pass the read-only adapter probe; all 35 portable histories restore exactly and their model contents match canonical order after applying exposure policy. Nineteen image objects pass byte checks and full in-memory decoding. Synthetic official CLI first/cold-reopen probes verify actual LocalAttachmentStore class/root and readImage bytes while DSH_HOME remains a different private home. Only diagnostics and synthetic resources are written during these probes.

Engine is versioned 0.1.32-rc2.2, adapter package 0.1.1. The paired Plugin is 0.2.25-rc2.2 because its host gateway bundles the changed V3 codec and migration helpers; the exact archive is embedded in the Engine package. Runtime attestation requires the new Engine version. Final Launcher activation and full user UI/Bridge/restart acceptance remain separate; do not deploy the old rc2.1 candidate as history-ready.
