## 为何没有立即进入真源

首次加入与后续自动回传是不同路径。前轮正式加入回执已确认 workplace1 既有测试会话在真源；“计算机四大”的新测试会话仍只有宿主记录。

代码确认的阻塞关系：

1. InstanceWorkspaceService.save 先持久化范围，再等待 alignOne 完成，最后返回配置；所以范围已保存仍可能长时间没有界面回执。
2. EndpointSyncCoordinator 的对齐经过全局写入协调；宿主回写失败会使状态 blocked。
3. HostSessionSync.pass 在非 active 时，在读取和回传新会话之前就返回；因而回写失败连带阻止了宿主中新会话的导入。

这是现有实现的缺口，不是用户需要再选一次工作区，也不是预期等待下次启动才导入。前轮实际宿主返回 HTTP 409 / HOST_SYNC_INCOMPLETE；内部失败阶段尚无足够证据，不能将排空超时推测当作确诊。本轮 UI 回退未修改这些后端路径，保存等待和运行期回传仍未完成修复与验收。

后续需分别处理持久化保存回执与对齐进度、准确暴露宿主失败阶段，并在保持启动权威、版本及独占写入保护的前提下修正导入依赖；不能简单放开 blocked 状态下全部写入或直接覆盖运行中的文件。
