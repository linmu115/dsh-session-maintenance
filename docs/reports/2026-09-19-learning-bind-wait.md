# 学习关联持续等待：排查、修复与部署边界

## 问题与现场证据

来源：用户在本次 Codex 任务 `01a0b8bb-ae8e-7202-af8d-ed8d46b04487` 反馈，选好会话和 Codex 目标后点击“核对并加入”一直显示“正在核对关联”。最初“失败”的描述经用户纠正为持续等待；不能将认证过期或活动实例保护直接当成本次卡住的根因。

2026-09-19 只读检查对象：实例 `i-7ecb6c19-80a5-4c2e-97e6-484bbfc0e926` / `web`，当前 origin `http://127.0.0.1:8008`，boot `0b0ca52c-7221-45d2-a7a8-729ae97d00d1`，run `run-a34ea704-4431-4839-9206-007b7b108d97` 为 running。维护 Engine .46 在本次连接描述符提供的端口 43788，health ready=true；数据库以只读方式检查，没有未提交 run_operations。学习关联数为 0，候选均属于该活动 run。

真实旧引擎上，使用保证不存在的候选身份请求学习关联，8,050ms 后客户端超时，未得到本应返回的不存在错误；此探测不可能创建绑定。GET 学习目录和 health 正常。源码显示 bind 的候选校验原先位于串行 writer 入队之后，且该入队没有传取消信号或等待期限，客户端也没有学习请求期限。证据支持写路径等待未设限；现有公开诊断没有暴露占用队列的具体操作，**尚未确定当前队列长期不推进的最初触发方**。

浏览器旧标签页另有凭据失效提示；正式 Open-Maintenance 入口恢复登录，未停止或重启任何实例。这个独立问题的恢复不构成学习关联修复验收。

## 本次修改

- Engine .47：首次绑定先做只读候选/活动实例检查，不再为了拒绝已知不可关联的候选而等待 writer；入队后仍重新核对身份、端点及运行状态。
- 学习写请求等待队列最多 5 秒，超时返回 `LEARNING_QUEUE_TIMEOUT` / HTTP 503，明确“尚未开始并已取消”。HTTP 断开也取消尚未开始的请求。已开始操作仍持有 writer 到完成，不因客户端断开或计时到期提前释放。
- Dashboard .10 / API client：学习目录及操作请求最多等待 45 秒。写请求超时表达“结果尚未确认”，不重试、不声称已取消服务端写入；状态刷新失败保留原操作错误并撤下过期候选。
- 候选目录提供活动实例阻塞原因、目标 Codex 实例身份；页面提前提示并阻止无效提交。新字段可选以兼容旧 Engine，旧端仍依赖最终校验。
- 发行版本校验登记 Engine .47；打包时发现仓库已提交的插件 .32 未在两处接入名单登记，同步补齐该明确版本。未知版本、能力与精确构件验证保持拒绝规则。

## 未完成与安全边界

新引擎/看板未激活；新 UI 的真实浏览器交互未验收，仅组件与合成后端验收。没有绑定真实会话、同步/回收正文、修改 Vault 或同步名单。当前实际运行版仍是 .46 / Dashboard .9，不能写成现场故障已修复。

正式切换前须通过 Launcher 正常停止目标 DSH，验证 flush/drain/close 与最终回执，再按已核验的 Stop-Maintenance 停引擎、备份并安装。本工作区 AGENTS.md 和开发验收文档明确禁止以直接 shutdown、杀进程或修改运行数据库代替 Launcher 停止；当前无可调用的外部 Launcher Stop 协议，因此本轮没有尝试绕过。还需在可安全激活后检查 writer 占用原因并完成用户选定会话的真实关联验收。
