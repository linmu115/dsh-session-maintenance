# RC2 测试实例插件迁移与 Maintenance rc2.33 发行

## 用户要求与处理结果

2026-09-19 用户要求把 RC2 副本的全部插件迁移至新建测试实例，并在发现 Maintenance 安装文件与旧包不同后，要求从最新源码打包、使用新包、提交推送。

旧安装清单固定在 `0.2.26-rc2.29` 的历史组合包，已安装 `lib/client/index.js` 与该包不一致。但它与本分支最新源码重新构建的客户端完全一致，SHA-256 为 `740d549f99f131f72233487e06d9af76301829d0811681e1213a7841ffd3f8e4`。已有源码包含完整 Dashboard 入口改动；无需从编译文件逆向补源码。

本次将源码插件由 rc2.32 升至 **0.2.26-rc2.33**，通过既有构建及 prepack 流程重新生成完整安装包。包 SHA-256：`dad68c1b31fb78766029856b7651cbccdc0be3fc16f27f20dde063071ac421a4`。测试实例已使用此新包，未使用最初为了保留安装差异制作的临时候选。

## 迁移与验证

- 目标 profile 为 `web`，迁移 19 个插件及支持包，保留源启用顺序；Maintenance 和 Bridge 的配置指向目标自身实例 ID。
- 18 个其他包维持源安装版本；Maintenance 来自本次完整源码构建。最终插件 1,161 个文件与预期逐项一致。
- 源 profile 的引用界面配套组件被制成独立本地包，63 个文件一致；目标依赖不再链接源实例或隔离安装目录，其余宿主依赖使用目标自己的 DSH 0.1.5-rc.2。
- 隔离安装与实际目标均通过严格 peer 安装。迁移安装过程中发现隔离 lockfile 的相对 tarball 路径不可原样跨目录使用，已按原目录解析路径并在目标重新安装，最终文件校验通过。
- 插件测试 **27 个文件 / 123 项全部通过**，插件类型检查与构建通过。修正测试中硬编码旧包版本、以进程工作目录定位源码的两处问题；后一项改为按测试文件自身位置查找工作区。
- 目标安装前已备份配置、凭据与原有存储文件；源插件 1,165 个文件、目标原有的 3 个非 profile 文件、Launcher 实例目录配置均保持原状。
- 测试实例保持停止。没有复制历史会话、Vault 绑定、同步策略、运行任务或执行日志，没有发起模型调用。源运行实例继续使用既有安装，未在运行期间替换其插件。

## 验收边界

本次完成包、配置、依赖和文件一致性验收。未启动目标实例、未验证维护引擎对新实例的实际托管接入，也未完成插件业务、引用往返及 UI 验收。新实例的模型账号和宿主模型配置仍按其自己的配置处理；复制插件不等于复制源账号。

本地迁移回执包括 `verify-target-receipt.json`、`preservation.json` 与目标安装日志，保存在本任务迁移产物目录，不将用户凭据或历史正文放入仓库。

## 开发过程

最初以源实际安装文件为准制作隔离候选。用户要求正式源码发行后，核对源码与安装文件、重建完整 rc2.33，并以该包替换候选。迁移时另发现源引用 UI 的 profile 内链接，需要冻结为独立包，避免让新实例继续依赖源实例目录。当前会话的正式来源索引待绑定，本文只记录有本次工具回执支持的过程。
