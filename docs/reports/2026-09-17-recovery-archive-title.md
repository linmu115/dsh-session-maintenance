# 重启重复会话、归档与旧派生标题修复

## 用户要求与验收

2026-09-17 用户报告官方归档后重启再次出现“机试DeepLearning”，点击后标题变成工作目录名，并明确要求执行修复。范围为准备事件恢复、归档投影和现存旧派生标题；不删除历史或按同名合并正文。

验收：纯准备尾部不创建派生历史；含真实事件的混合尾部完整保留；已归档 canonical 会话经官方宿主归档 API 隐藏，缺失标记不撤销宿主归档；旧派生会话通过官方重命名补写标题且原消息序号不变。现存重复项需先验证差异只有准备事件，再归档而非删除。部署保留回退包和数据库备份，重启后复核。

## 诊断与开发历程

本任务可见用户消息与只读工具检查为来源，详细事件索引待绑定。真实数据库显示旧归档仍存在，2026-09-16 的恢复操作额外创建两个派生 ID；其中一个 canonical 已归档但宿主未归档。原始镜像已有标题事件，三个旧派生文件没有标题事件。

恢复 WAL 的既有过滤没有覆盖新扫描的原生尾部。Adapter 的目录 payload 未携带 archivedAt，宿主启动无法恢复这项状态。旧派生序号不可挪动，因此标题采用官方尾部追加修复，不重排消息。

## 实施与验证

Adapter / GPT 扩展 / projection lifecycle / 宿主归档与目录测试 26 文件、140 项通过；随后补充归档字段和完整准备尾部恢复测试，针对的 15 项通过（包含上述既有测试）。Adapter 与插件类型检查通过，完整 workspace 构建通过。构建时暴露 GPT 扩展导出推断依赖私有路径的问题，使用宿主 Adapter 的显式公开类型修复，运行行为不变。
