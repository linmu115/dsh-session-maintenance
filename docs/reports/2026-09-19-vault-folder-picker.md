# Vault 文件夹窗口延迟和超时

## 用户问题及证据

2026-09-19 用户在 Maintenance 为实例新建 Vault 绑定时，文件夹窗口没有及时出现，网页报超时，随后又反馈三五分钟后窗口弹出。晚到窗口的具体来源未能确认：同一期间曾启动一个不会提交绑定的独立诊断选择器，不能把窗口弹出当作正式绑定成功。

当前安装 Engine 0.1.33-rc2.54 的实现使用 Windows PowerShell 5.1 的 WinForms FolderBrowserDialog，并让初始化及人工选择共用 60 秒超时。隔离复现中，原选择器在 30 秒测试上限内未完成；中途辅助进程没有主窗口句柄。单独测量 PowerShell 启动及 WinForms 加载共 775 ms，组件加载 108 ms。证据将延迟范围缩小到后续 Shell 选择器阶段，尚不能确认是网络位置、Shell 扩展还是窗口显示时序。

## 实现

Engine 0.1.33-rc2.55 使用 Windows 原生 Common Item Dialog 的文件夹模式，无需新增 PowerShell 7 依赖。固定脚本从本机用户目录开始，避免恢复不可达的上次访问位置；只接受文件系统目录，不写最近访问记录。路径仍通过 JSON 返回，再由现有 Vault/Bridge 身份校验和正式绑定流程验证，路径不拼入可执行脚本。

启动阶段限时 20 秒；原生对话框首次报告目录初始化后，独立给予 10 分钟人工选择时间。后续切换目录不重置等待上限。请求断开或超时时终止本次独立选择器辅助进程，区分未能打开、人工选择超时及取消。无选择结果时不创建绑定操作，不改同步策略。

## 开发历程草稿

用户连续反馈迟迟不弹窗、超时及数分钟后弹出。先核查当前网页失败状态与原实现，隔离测试不调用绑定；排除基础进程启动慢后改用原生 Common Item Dialog，同时分离启动与人工选择的期限。Windows 内部延迟原因仍未精确证实，新实现的改善仅有独立本机窗口和后端证据。保留原始问题与边界，正式会话来源索引待绑定。
