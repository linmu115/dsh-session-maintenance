## 原因与实现

真实目标“机试DeepLearning”的 Codex 日志有 3 次压缩。旧学习读取器遍历压缩前后所有记录，省略公开 commentary，未采用普通导入的引用批注/委派封装处理；普通导入还会去掉用户消息外围空白。这使两个读取路径得到不同序列，不能据旧错误断言真实正文分叉。

只读对照普通导入的有效历史与当前 DSH 投影，49 条消息逐条一致。修复复用 Codex Read adapter 的最新 replacement_history 和公开用户文本处理，保留公开进度消息；比较仅归一化用户正文外围空白，内部字符差异仍拒绝。原始日志摘要仍涵盖全部行；交接后压缩、回滚、中断、工具执行及非图片未知材料仍阻止追加。回收支持同一完整轮次内多条公开助手消息，原文不合并、不丢弃。

`learning_bindings` 是普通同步排除的持久化依据，与接管主线在同一事务提交。普通项目同步的扫描名单和显示计数排除这些来源；启动完整性检查不再要求它们是 Codex 镜像。名单清理保留尚未删除的学习主线及已有合法 DSH 派生进度，不能通过项目选择复活已删除的学习会话。排队中的旧导入计划先核对学习归属，再检查其已过期的普通同步范围，不执行正文推进和重新分配。已有绑定无需再次点击即可生效；停用实验关联不会自动交还普通镜像所有权。解除的是普通 Codex 导入，不移除 DSH 投影或整个项目的其他会话。
