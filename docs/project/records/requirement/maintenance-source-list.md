# 用户要求与验收条件

来源：2026-09-19 当前任务用户文字及三张截图。保留 DSH 实例选择；同步范围模仿 Codex 项目映射名单，默认折叠，点击三角形展开，选择对象为 Maintenance 真源工作区。

展开后支持搜索、勾选、已选计数及工作区详情；保存和撤销沿用现有实例策略及修订校验。全部范围包含未来新增工作区，指定名单包含所选工作区未来会话，两者明确区分。保存仍在下次启动生效。不得为 UI 验收修改真实名单。

**2026-09-21 用户注释部分替代**：同步工作区**默认全部不勾选**，且工作区不再随之自动进入真源；新增工作区要通过**原本的右键操作菜单**「将当前工作区加入 sessionmaintenance」显式加入，由 Maintenance 引擎启动时接纳。上述「全部范围包含未来新增工作区」的重合语义如何调整尚未确认。见 [[DEC-directory-connect-sync-authority]]、[[REQ-detached-instance-attach-sync]]。

**2026-09-21 后续一轮的用户修正（同一会话）**：不存在「历史默认范围／legacy all」——**未显式选择即为空**，新接入与存量实例一视同仁；某实例同步哪些工作区就等于它在 Maintenance 面板里显式选择的那批。后果：原先依赖「无记录 = all」的已接入实例升级后范围变空，直到用户在面板里勾选（受影响实例清单由另一个任务只读核查，不在本记录）。另外，用户提出「连接上之后可以让 DSH 侧也提供修改同步范围的选项」记为**可选**、不是本轮必须实现，若实现需新增实例侧界面入口。见 [[DEC-directory-connect-sync-authority]]。
