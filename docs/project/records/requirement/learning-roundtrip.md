# 实验性学习会话双端交接与受控回收

## 用户范围与当前进度

2026-09-17 用户明确：作为 Session Maintenance 测试性功能，完整看板独立增加栏目；只纳入确认双端关联的会话，首个目标为“机试DeepLearning”。仅处理轮流使用 DSH 与 Codex 的学习型问答，不扩展至开发执行环境同步。来源与修正过程见 [[HIST-learning-roundtrip]]。

2026-09-17 已完成受控首版代码及隔离验证，见 [[IMP-learning-roundtrip]]、[[VER-learning-roundtrip]]；尚未部署或绑定真实“机试DeepLearning”。本记录仍保留完整目标，未把首版限制改写为用户要求。

首版需要停止 DSH 后交接、同步成功后重启 Codex，再继续原任务；不能热更新已加载的桌面上下文。仅验证 RC2 与 Codex CLI 0.153.4 的 legacy 历史。已有共同前缀不一致、图片、上下文替换、回收增量含工具执行时阻断；跨 DSH 实例重新选端点仍待实现。同一来源路径迁移可显式重新核对，使旧交接失效。

## 使用入口

完整看板新增“学习会话双向维护（实验）”独立栏目。仅列出经过明确确认、已核对实际端点的绑定，不自动按标题配对，不自动纳入其它镜像。每项展示逻辑会话、两端身份、同步/回收状态和失败原因。

两项主要操作为“同步到 Codex”和“回收 Codex 会话”。都由 Maintenance 看板发起，不依赖修改 Codex 前端，不以额外对话或模型调用完成控制操作。DSH 会话菜单入口可作为后续便利入口，不作为首版交付前提。

## 唯一身份与正文

一项绑定对应一个 Maintenance 逻辑会话、一个当前 DSH 原生端点及一个 Codex 任务。原平台 ID 保留各自作用域。首次接管明确选择主线和共同历史，不能按同名合并。初期优先复用现有 Codex 任务，兼容性待验证。

启用后的 DSH 正常续写推进该逻辑会话的版本，不能触发默认 Codex 镜像首次续写的派生规则。绑定端点的 Codex 观察先路由到此模式，不能被普通扫描器再次导入为新镜像。冲突禁止自动追加，不自动新建任务、派生身份或拼接分叉。

Maintenance 始终保留完整主线。Codex 回收只接收已确认边界之后的新增问答，不以 Codex 的界面列表、可见历史或压缩后上下文替换整条真源。DSH 已有问答、顺序、稳定锚点与扩展关联继续保留，成功回收后仅补齐新内容。

## 输出过滤与引用上下文

携带用户问题和正式回答，保留角色、顺序、Markdown、公式和正文代码示例。将该轮实际使用的引用文本快照及必要来源说明作为附带上下文携带，与用户原话分开标识。引用变化不追溯改写旧快照，往返回收不能再次把快照拼入正文或重复投影。

思维图、贴纸、Obsidian 双向关系及扩展对象继续存于 Maintenance，不投影到 Codex；工具执行、内部推理、平台运行配置不视为学习问答。对端缺失扩展数据不能解释为删除。图片或不支持的材料需明确显示未携带范围，不声称已完整送达。

## 同步与回收条件

用户要求：两次点击之间 DSH 没有新增会话内容，且 Codex 的最后一次新追加发生在上次同步点击之后，才允许回收；出现两端分支差异禁止追加。

实现应在保留上述条件的基础上使用稳定版本和游标，时间只作辅助。以下为完整验收要求；已实现范围及剩余限制以实现、验证记录为准：

1. 同步时确认两端无进行中的生成和未处理增量，保存同步点击时间、DSH 学习正文的单调修订号与内容摘要、Codex 已观察边界及绑定代次。等待 DSH 写入完整提交，不只读取可能滞后的数据库头。
2. 将缺少的学习正文与引用上下文投影到绑定的 Codex 任务，记录每个导入项与 canonical 消息的对应关系。成功核验接收后保存投影后的 Codex 边界和成功时间，建立唯一交接回执。同步期间出现任一端的新问答则本次交接不能标为可回收。
3. 回收必须持有最近一次成功且未消费的交接回执。没有成功同步、绑定代次变化或状态不确定时禁止追加。投影产生的注入项不能算 Codex 新问答，不能仅凭“最后事件时间较新”放行。
4. DSH 学习正文修订号必须与交接基线一致；新增、修改、删除后即使恢复原文本也不能规避检查。只改标题、布局或不影响学习上下文的扩展元数据不算问答分叉。任何影响已交接上下文的变化须使交接失效。
5. Codex 必须仍对应同一任务及边界，已有学习历史未被改写，新增部分为完整、顺序确定的问答；新增生成须在同步成功后开始，最后追加发生在同步点击之后。同步前已启动、同步后才完成的旧回答不能冒充新进度。正在生成的尾部暂不回收。
6. 提交回收时再次核对两端修订与边界，Engine 对交接记录和 canonical 头执行并发检查，以事务追加、登记来源映射并消费回执。无法阻止宿主并发写入时必须检测并拒绝，不能只在点击瞬间检查一次。不能保证边界稳定的版本不得开放功能。
7. 无新问答时返回“暂无新增内容”，不生成版本或会话。重复点击复用结果；回执不确定先核验既有落盘，不盲目重新注入或追加。DSH 展示更新失败可重试物化，不得重复收回同一批问答。

用户所说的“锁”是由 Engine 实施的追加条件与冲突阻断，不宣称能禁用 Codex 前端输入。检测到 DSH 已推进、Codex 历史被改写或边界无法确认时，显示具体原因，保留两端原内容，不自动合并。

## 继承迁移维护能力

绑定、交接回执、来源映射和去重身份纳入 Maintenance 的持久化与迁移维护范围，复用逻辑会话的版本、检查点、归档和恢复机制，不另建脱离真源的正文库。迁移保持 logicalSessionId 与历史；宿主原生 ID、路径、实例及可用性应重新核验。

迁移导致任一端点变化时增加绑定代次，旧未完成交接不得套用到新端点；端点缺失显示待重新关联，不按标题自动认领。恢复旧检查点不能把已消费回执当成可再次追加的许可。移除实验绑定不删除学习正文或原平台任务；归档、删除、回滚及端点替换应阻止未完成交接继续写入。具体存储迁移与恢复冲突策略在实现中补充验证。
