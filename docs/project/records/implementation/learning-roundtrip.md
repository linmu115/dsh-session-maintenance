# 学习双向维护的当前行为与边界

当前安装为 Engine **0.1.33-rc2.53** / Dashboard **0.1.13**，代码提交 af2c5c7。真实目标“机试DeepLearning”已关联，49 条有效历史核对通过，普通 Codex 同步已自动排除。2026-09-19 18:11 完成空增量交接，目前等待回收；18:20 正常重启引擎后关联、回执和历史保持不变。

## 如何使用

1. 首次在“学习双向维护”中选择同一条 DSH 投影和 Codex 来源，核对并加入。图片仅在学习交接中跳过，混合消息保留文字、纯图片保留占位，原图片不删除。
2. 在 DSH 中完成新增问答后，通过 Launcher 正常停止 DSH，等待收尾，再点“同步到 Codex”。系统只追加已绑定任务尚无的文字问答及已有可识别的引用上下文快照。
3. 有新增内容时显示“已追加 N 条消息”，重新启动 Codex、打开原任务继续学习。没有新增内容时显示“两端文字已一致，无需追加”，仅保存交接边界，不重复注入。
4. Codex 新回答完成后点“回收 Codex 会话”，只收回成功交接后开始并完成的问答，追加到原 DSH 逻辑身份；再启动 DSH 继续。

同步按钮不会自动跳转、打开任务或触发模型回答；导入历史不保证逐条呈现为聊天气泡。另行新建的独立 DSH 会话需要独立关联，不被现有按钮批量纳入。思维图、Obsidian 关系等扩展对象不送入 Codex。

## 归属与冲突保护

加入双向维护时，学习关联与主线接管在同一事务提交。普通 Codex 项目扫描、启动核验和名单清理共同识别学习归属；排队中的旧导入计划也会跳过，已有绑定重启后仍有效。仅排除这条来源，不取消同项目其他会话或 DSH 投影。停用关联保留主线和交接记录，不自动恢复普通镜像覆盖。

有效历史读取采用与普通导入相同的最新压缩替代历史和公开文本规则，公开助手进度保留。仅归一化用户正文外围空白用于核对；真正正文分歧仍拒绝。Codex 原始日志摘要覆盖全部行，回收前再次检查双端状态。发送预算只计算本次增量，不重复计算共同历史；超限报错，不静默截断。

绑定和交接共用引擎独占写队列；等待超时的排队操作取消，已开始写入不会因客户端断连提前释放。正文推进和回执消费在同一事务，重复回收不重复追加。正文修改、归档和删除增加修订，标题变化不会误锁正文。结果未知时先“核验同步结果”。
