# 2026-09-22：同步责任归 Adapter

来源：当前 Codex 任务中的用户消息，尚未绑定正式事件索引。

只读复核发现，已有局部测试通过并不意味着普通运行的双向同步可用。用户要求继续实现，同时纠正责任边界：Maintenance 主体不能耦合实例、Launcher 或其他插件，具体接入必须留在 adapter。实现从拆分物理读写与通用同步规则开始，保留现有未提交修改。

关联：[本轮要求与实现](../../changes/2026-09-22-adapter-owned-workspace-sync.md)。

本轮拆出通用同步阶段/版本/范围协调器，把原生格式、物理目录和宿主快照处理移到 adapter，并修正归档参数白名单、真实持久化快照形状、已有会话绑定补登记和内容漂移识别。合成存储往返覆盖新建、追加、标题、归档和工作区变化；旧 epoch 删除不能回放。

测试过程中发现规范事件对象键顺序不同不应判为历史被改写，改用深比较；非消息事件 role 不能写 null；首轮观察和对齐之间的变化需以刷新补偿。扩大测试中剩余 6 项失败在改动前独立副本复现，未将这些既有问题混入本轮修复。

最终相关 69 文件、369 项测试通过，全仓类型检查和构建通过。独占宿主写入与归档恢复没有真实提供者，改为明确阻止对齐，避免把私有标记当作恢复成功。整个 Engine 的遗留耦合和部分派生组合仍未完成。未发布、未部署、未做真实写入或 UI 验收。保留原有 5 个未提交路径。
