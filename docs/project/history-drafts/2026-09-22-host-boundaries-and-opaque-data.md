# 2026-09-22：宿主边界与未知数据折叠

来源：当前 Codex 任务中用户确认核心、宿主 adapter、业务 adapter 的职责，并补充“无法识别的未知结构化数据统一打包映射并折叠不展示”“launcher 应该解耦出 maintenance”。整理者为本任务 Codex；尚未绑定正式事件索引，未导入其他会话。

本轮先保存用户确认的边界，再迁出安装、目录选择、Launcher 配置、租约和系统证据实现。原宿主 adapter 的通用加载器依赖来自 Engine，随之迁入 adapter-host；运行记录查询改为注入接口，避免产生 adapter 回调导入 Engine 的依赖环。

图对象存储和归档初始化迁入知识业务 adapter，核心只发布会话状态通知。合成测试验证 adapter 错误会回滚规范事务；未安装宿主/业务 adapter 时，会话存储和归档仍可独立完成。未知事件增加无损映射数据包，前端折叠且不请求正文；实际 SQLite/对象存储往返验证保留原记录。

初次新测试因漏传阅读查询参数失败，补齐参数后通过。最终组合 90 文件、466 项中 465 通过；另一个失败为前轮基线已复现的扩展校验错误文本断言。全仓类型检查、构建通过；最后阅读器局部复核 13 项通过。实际运行实例和 UI 视觉未验收。

架构检查仍发现图/引用/GPT 索引、插件目录规则、宿主阅读格式的旧入口耦合，因此整体解耦未完成。真实宿主独占写入和取消归档协议也未接通；维护核心不承担 Launcher 停机职责。结果与后续边界见[本轮变更报告](../../changes/2026-09-22-host-boundaries-and-opaque-data.md)。
